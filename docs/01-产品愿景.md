# 01 产品愿景

## 一句话定义

用国产大模型驱动、面向非开发者的中国版 Codex,也是一个面向办公场景的桌面级 agent 助手。把「会写代码的 agent」复刻成「会在你电脑上替你把活干完的 agent」,对标 WorkBuddy、Trae Work、Coze 的下一代办公入口,让 agent 能在电脑上替知识工作者把文档、表格、网页、企业系统和跨应用流程做完;用「工作台」打包成普通人点开就能用的岗位,用「市场」让办公能力人人可造、可传、可赚钱。

## 我们要解决的真问题

今天最强的 AI agent(Codex、Claude Code 这类)有一个共同特征:**它们真能在一台电脑上干活**——读写文件、跑命令、联网、调工具,而不只是聊天或调几个 API。与此同时,WorkBuddy、Trae Work、Coze 正在把 agent 推向办公桌面:浏览器、文档、表格、会议、企业系统和跨应用流程会成为下一代办公入口。但这份能力仍被锁在两道墙后:

1. **形态墙**:它们是终端里的黑框,面向程序员。
2. **表达墙**:用好它们要会写精确、结构化的指令——这是程序员的本能,却是普通人的天堑。

结果是:一个行政、运营、销售、财务、人事、跨境卖家、内容团队都用得上的强力工具,实际上仍主要被程序员或少数高阶用户掌握。

2049 App 的使命,就是**拆掉这两道墙**,做一个非开发者版 Codex / 中国版 Codex:先聚焦办公场景,让运营、行政、财务、人事、销售、跨境卖家、内容团队——任何不懂代码的知识工作者——都能丝滑地用上 Codex 级别的桌面 agent 能力,不必懂代码。

### 更深一层:拆掉墙之后,agent 去开每个软件的「机器门」

为什么天花板远不止「办公」?因为几乎每个成熟生产力软件都长着**两道门**:

- **GUI 门**:给人手用的,一次一个动作、靠手点、不可复现。普通人这辈子只走这道门。
- **机器门**:给机器驱动的(脚本 / 宏 / API / 格式层),能批量、精确、可复现——前提是你会说它的语言。

两道门通往**同一个引擎**(Excel 的菜单和 VBA 操作同一个计算核;AutoCAD 的鼠标和 AutoLISP 走同一个几何核)。机器门一直开着,却被「编程 + 工具选择 + 调试 + 文件格式知识」锁住,把真正有业务需求的人挡在门外。

**两道墙讲的是「钥匙(agent)被锁起来」,两道门讲的是「钥匙能开什么」——它俩接在一起:** 拆掉两道墙 = 把这把万能钥匙交给普通人;agent 拿到手后,去开的正是每个软件的机器门。**插件 = 每个软件机器门的适配器**(Office、PDF、图像、CAD、GIS、财务……完整目录见 [.specs/004](../.specs/004-plugin-catalog/))。

这定了能力的两个面:**横向底座**(文件 / PDF / 图像 / Office / 网页搬运等通用机器门,人群最大、最先铺满)给所有工作台共用;**纵向深水**(CAD / BIM / GIS / 财务等专业机器门,单座价值高)逐个垂类纵深。注意:**能力目录可以广(reach-first 全造),但市场进入仍是极窄切入、单垂类先行**(见 [06 市场与创作者经济](06-市场与创作者经济.md))——铺货的广度 ≠ 打仗的广度,这与「不做大而全的通用助手」不冲突。

> **分批节奏(2026-06-29 定,消除「极窄切入 vs office MVP」的表面矛盾)**:office 工作台是**第一批官方工作台**,定位是**横向底座、强化自身能力、练兵夯基**——它有意选了最稳、最现成(Hermes skill 白嫖、零生成成本)的方向,**不是窄楔子**。真正的「极窄切入单垂类」战略放在**第二批官方工作台**(垂类待定)。所以「极窄切入」描述的是第二批的打法,不是 MVP 的 office;两者是分批次的有意安排,不冲突。MVP 阶段不深究战略楔子。

## 为谁做

| 用户层 | 是谁 | 怎么用 |
|---|---|---|
| **小白(主力)** | 办公岗位与中小团队成员,不懂代码 | 点进现成的「工作台」,按引导把活干完 |
| **进阶玩家** | 懂一点、爱折腾的人 | 用自由对话 + 直接调插件,自定义流程 |
| **创作者** | 懂某行业 know-how 的人 | 造工作台/插件上架,赚钱 |

注意:三层是递进的。绝大多数人从小白入口进来,少数变成进阶玩家,极少数成为创作者——而创作者产出的内容,又服务于下一批小白。这是平台的飞轮。

## 核心信念

**1. 普通人要的是结果,不是搭建工具。**
Coze、Dify 那类「拖拽节点搭 agent」的平台,本质还是给会拆解问题的人用的。普通人面对一张白纸会懵。所以我们不让小白「搭」,而是给他一间**已经布置好的房间**(工作台),他只做有意义的决策。

**2. 传播框架,而非成品。**
过去做一个垂直工具,要开发一整套软件再交付成品。但现在人人手里都有 agent 这把「厨具」,我们只需传播「厨房 + 菜谱」,食材让 AI 自己上网找。这让「一个引擎 + N 个低成本工作台」在经济上成立——每个工作台是一个轻量垂类楔子,而不是一个完整产品。

**3. 不锁模型。**
大厂工具免费,是因为要卖自家模型。我们没有模型要卖,所以可以中立地把全网国产模型摆上货架让用户自己挑(按任务自动选的 Auto-Mode 是大后期方向)。这是大厂商业模式上学不来的中立性。

**4. 安全是「敢用」的前提,不是附加项。**
让普通人看着一个 agent 在自己电脑上执行操作而不恐慌,靠的是 Codex 那套沙箱 + 审批体系。这既是技术底座,也是信任卖点。

## 为什么是现在

- **国产模型够强了**:2026 年 DeepSeek、Qwen、GLM、MiniMax、豆包等在 agent、写作、多模态上已成梯队,且国内直连、性价比高。v1 官方支持 DeepSeek,其他厂商由用户在模型广场自加(见 [05 模型路由](05-模型路由.md))。
- **范式已转向 agent**:从「调一个 API」到「感知—规划—执行—反馈」闭环,工具调用与 computer-use 成主战场。
- **「机器门」被攻打了 40 年,AI 是第一把同时给「能力 + 易用」的钥匙**:宏录制(易用但脆、不分支)、VBA/AutoLISP/ExtendScript(全能但要编程)、Zapier/RPA(零代码但只能用预置连接器、又脆又贵)——每一代都在「能力 ↔ 易用」之间二选一。AI 第一次两头都给:它能写真正的脚本/宏/API(完整能力),又只需自然语言(高易用),把「工具选择 + 调试 + 格式知识」这三项税消化进模型里。代价是用「确定性」换来的(它灵活但不总是对)——这正是 ④验证层要补的账,见 [03 系统架构](03-系统架构.md)。
- **窗口期有限**:字节 Coze 已在往「能操作电脑的 agent」走。我们必须快,且必须在它结构上做不到的地方建立护城河。详见 [02 市场与竞品](02-市场与竞品.md)。

## 不做什么(边界)

- **不进编码工具的红海竞争**:不去正面打 Codex / Claude Code / Cursor / Trae / 通义灵码。但我们**有** CODE 入口——它是**技术跟进**:白嫖 codex app 的强编程能力(照抄、汉化、接国产模型),给会写代码的开发者用,**不投差异化、不抢市场**。即「有编码入口,但不打编码这场仗」。详见 [04 产品形态](04-产品形态.md) §六。
- **不做又一个「拖拽搭 agent」的画布**:那是 Coze/Dify 的主场,且对小白依然太难。
- **不做大而全的「通用助手」**:那是豆包/通义的主场,新团队上去是用短处撞长处。我们靠垂直工作台的深度切入。

## 成功的样子

普通人打开 2049 App,像打开一个 app 商店,但里面每一个「应用」都是一个能在他电脑上替他干完一整件事的 agent 工作台;懂行的人在这里造工作台赚钱;而这一切由国产模型驱动、数据可留在本地。
