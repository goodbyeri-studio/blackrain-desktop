# 08 仓库结构与上游策略

## 目录

```text
apps/desktop/      当前 Tauri 产品代码与 Electron 迁移目标
gateway/           可选协议翻译 sidecar
codex-upstream/    gitignored 的原装 codex 只读克隆
plugins/           暂停资产，主线按需复用
workbenches/       暂停的工作台资产
.specs/            living specs
docs/              战略、架构与运行手册
```

## 四类代码

| 类型 | 位置 | 规则 |
|---|---|---|
| 桌面产品 | `apps/desktop/` | React 可复用；Tauri 逐步迁出；Electron 是唯一目标宿主 |
| 当前 Tauri 后端 | `src-tauri/src/shared/*` 与 daemon | 作为迁移输入盘点；目标能力进入 Electron main/preload 或原装 app-server，最终删除 daemon |
| 模型适配 | `gateway/` | 独立、可选，不形成 agent runtime |
| agent 内核 | `codex-upstream/` | 原装只读，锁版本、构建、探针和回归，不改 agent loop |

`plugins/`、`workbenches/` 和相关 specs 是暂停资产，不属于当前主线分类。安全、License 或构建修复可以维护，功能扩建必须先重新决策。

## Codex 上游

锁定版本由 `scripts/fetch-references.sh` 和 [REFERENCES](REFERENCES.md) 维护。版本锁只证明源码身份，不证明协议、桌面集成、Browser 或 Windows 制品可用。

升级顺序：

1. 校验 tag 与完整 SHA。
2. detached 更新 `codex-upstream/`。
3. 构建需要的 codex/app-server 制品。
4. 运行协议和能力探针。
5. 更新 spec 006/013 的能力矩阵与状态。
6. 运行 Electron/Rust 集成和 Windows 关键 E2E。

不在 `codex-upstream` 直接提交 BlackRain 改动。确需上游变更时，优先形成独立 upstream contribution；本仓仍保持可使用原装发布版本。

## CodexMonitor 与 Tauri

`apps/desktop/` 由 CodexMonitor subtree 起步，当前代码仍包含 Tauri 目录、IPC 和构建链。它们是迁移输入，不是长期架构。

- 日常不随手执行 subtree pull。
- 需要参考上游时先做变更与 License 审计。
- 不再扩建永久 Rust daemon；按能力矩阵把 app-server 已有能力直接接入 Electron main，把桌面宿主能力迁入 main/preload。
- Tauri 专属 adapter、plugin、配置、脚本和 CI 按 spec 012 分阶段删除。
- 不为保持 subtree 同步牺牲 Electron 目标架构。

## Electron 产品代码

Electron 目录建立后至少区分：

- `main`：App Server client、桌面特权与 browser 生命周期
- `preload`：类型化最小 IPC
- `renderer`：React UI
- `shared contracts`：跨进程类型与 schema

最终布局由 spec 012 决策。在代码存在前，文档不虚构可运行命令或产物路径。
