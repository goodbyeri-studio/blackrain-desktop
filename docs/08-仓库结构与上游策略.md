# 08 仓库结构与上游策略

## 目录

```text
apps/desktop/      Electron Desktop 产品代码
gateway/           可选协议翻译 sidecar
codex-upstream/    gitignored 的原装 Codex 只读克隆
plugins/           暂停资产，不进入当前产品主链
workbenches/       暂停的工作台资产
.specs/            living specs
docs/              战略、架构与运行手册
```

## 代码所有权

| 类型 | 位置 | 规则 |
|---|---|---|
| Desktop | `apps/desktop/electron`、`apps/desktop/src` | main 持有特权与 App Server/Browser，preload 最小 allowlist，renderer 只负责 UI |
| 模型适配 | `gateway/` | 独立、可选，不形成 agent runtime |
| agent 内核 | `codex-upstream/` | 原装只读，锁版本、构建、探针和回归，不改 agent loop |
| 暂停资产 | `plugins/`、`workbenches/` | 只作历史/兼容保留，功能扩建前必须重新决策 |

迁移前的 Rust 宿主和 daemon 已删除；历史 command/import 只在 `.specs/002-electron-migration/migration-ledger.json` 保留审计记录，不是当前代码入口。

## Codex 上游

锁定版本由 `scripts/fetch-references.sh` 和 [REFERENCES](REFERENCES.md) 维护。版本锁只证明源码身份，官方 Windows package 还必须通过 archive、逐文件 SHA-256、License/NOTICE 和 Authenticode 校验。

升级顺序：

1. 校验 tag 与完整 SHA，detached 更新只读 `codex-upstream/`。
2. 更新 runtime lock 与 canonical package hash/签名身份。
3. 运行 App Server、标准 Home、Browser MCP 和 helper 协议探针。
4. 运行 Desktop typecheck/test/lint/Native Clean/package/smoke/E2E。
5. 在正式签名候选上完成适用的 Windows 产品矩阵。
6. 同步 `002` verification；若改变公共 Browser 合同，同时同步 `003`。

不在 `codex-upstream` 直接提交 BlackRain 改动。确需上游变更时形成独立 contribution；BlackRain 仍须能够消费原装发布版本。

## CodexMonitor 来源

`apps/desktop/` 由 CodexMonitor subtree 起步。日常开发不随手 subtree pull；同步前审计差异与 License，且不得恢复旧宿主、第二 runtime 或破坏 Electron main/preload/renderer 边界。
