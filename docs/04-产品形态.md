# 04 产品形态

> **本文是产品形态和优先级的唯一真源。** 运行时进程看 [09](09-运行时架构与里程碑.md)，整体迁移波次看 [10](10-Electron迁移与内置浏览器实现计划.md)，BlackRain 产品交付合同看 [002 Electron 全量迁移](../.specs/002-electron-migration/)，Browser 源码底座合同看 [003 可移植 Electron Browser Runtime](../.specs/003-portable-electron-browser-runtime/)。

## 产品第一主语

BlackRain 是 Codex-first 桌面 App。

用户打开产品后直接进入项目、thread 和任务执行，而不是先选择工作台、角色或 agent 内核。产品围绕一个持续可恢复的 Codex 工作流组织：

```text
项目
  -> thread / turn
  -> 文件、终端、Git、diff、审批、Browser
  -> 结果、恢复和继续工作
```

## 核心体验

### 项目与 thread

- 打开本地项目或工作目录
- 创建、切换、搜索、归档和恢复 thread
- 流式展示推理状态、工具活动、审批和结果
- 保持草稿、队列、停止和错误恢复可预测

### 工程 surface

- 文件与变更
- diff 与 review
- 终端和命令执行
- Git 分支、提交和 PR 工作流
- 上下文、模型和权限设置

### In-app Browser

Browser 是核心产品 surface，不是外链按钮或隐藏自动化：

- 页面在 App 内可见
- 登录态持久且与 App 权限隔离
- agent 和用户操作同一个 Browser tab 与页面 WebContents，不另起 headless browser
- agent 可通过 Codex 式高层 Browser API 执行导航、snapshot、locator、CUA、截图和受控 CDP
- 用户可随时接管并归还控制
- Browser 侧边栏隐藏时页面 WebContents 可继续运行，但 thread 中必须持续显示活动、origin、控制方和停止入口
- 截图、下载、权限、弹窗、外部协议和异常都有可见状态
- 页面和 thread 可以关联；Cookie、Local Storage、认证 token 和密码不被自动读取，显式 snapshot/截图中的可见内容可能进入模型且必须显示来源

Browser 功能和交互以 Codex App 的官方公开说明与合法可观察行为为第一基线。ClawX、Hermes Desktop 等项目只能提供打包、sidecar、session policy 和恢复方面的工程参考；它们的独立 agent browser 不属于 BlackRain 产品路线。

### 可移植 Browser Runtime 源码底座

BlackRain 同时把自有 in-app browser 整理为适合其他 Electron 编程工具和桌面 Agent 二次开发的源码底座。该底座复用同一个 main-owned `WebContentsView`、session、registry、CDP、安全和恢复实现，但把 BlackRain/Codex thread、turn、IPC、App Server 和 React UI 移到 adapter 边界。

- 交付形态是可 copy、fork 或 workspace 引用的低耦合源码、公共合同、adapter 和最小参考宿主；不是安装即用插件、通用 UI 或独立 Browser 产品。
- Browser 核心不拥有 Agent runtime；其他 Electron 项目可以不接 Agent，或实现自己的 Agent/tool adapter。
- BlackRain 仍是首个产品消费者，不能为源码底座复制第二套 Browser backend。
- 源码底座是否可移植看 `003` 的 `PORTABILITY_PASS`；BlackRain 是否可发布仍只看 `002` 的 Windows 产品矩阵。

## 优先级

### P0：Electron 全量迁移

唯一当前 P0 是把已完成 native-clean 代码迁移的 Electron 客户端推进到 Windows `PRODUCT_PASS`：

- 项目、账户、模型、thread/turn、审批、文件、Git、终端、设置和 Browser 全部使用 Electron/App Server 唯一路径
- renderer 的 Tauri 直接依赖和 Tauri command 迁移账本归零或明确删除
- 删除 Tauri runtime、BlackRain daemon、固定本地端口、NSIS 和兼容 adapter
- 签名 MSIX 的安装、首启、升级、回滚、卸载和 Windows 产品矩阵通过

Browser P0 的 runtime/功能链路已闭环：标准 stdio MCP + 随包 Node adapter、同页真实模型、locator/CUA、下载、权限、恢复和安全基础已有证据。真实站点、输入/显示和安装态场景继续作为 Electron 发布回归矩阵，不再阻塞全量迁移开工。

当前代码与 unsigned 制品已达到 `RUN_PASS`。首要阻塞变为正式签名证书/runner 及签名 MSIX 产品复验；2026-08-03 的全页面不可点击历史失败只有在正式候选上通过真实输入矩阵后才能关闭。

### 并行开发：可移植 Browser Runtime

`003-portable-electron-browser-runtime` 作为独立源码底座开发线启动，但不改变 `002` 的产品 P0 顺序。共享 Browser 代码的改动必须同时满足 BlackRain 产品回归与源码底座公共合同；reference host 通过不能替代签名 MSIX 验收。

### P1：Electron 发布后

- 核心项目/thread/审批/diff/终端体验缺口
- 桌面通知、快捷键、更新和恢复
- 性能、诊断、可访问性和 Windows 交付质量
- 当前锁定 `codex-rs` 新能力的产品化

P1 的具体排序必须来自能力矩阵，不按旧工作台路线自动继承。

### 暂停

- 工作台 Manifest、安装、激活、升级与卸载
- Session Orchestrator 与 workbench surface
- Office 参考工作台
- 插件市场、专家市场与创作者经济
- OPC/工作室、多角色和多 Agent 公司编排

“暂停”表示代码与文档资产可以保留，但不进入当前导航、发布承诺、里程碑或自然扩建。重新启动必须有新决策。

## 内核与宿主边界

| 能力 | 所有者 |
|---|---|
| App Server client、窗口、Browser、权限、下载、更新、系统集成 | Electron main |
| thread、turn、工具、审批、沙箱、恢复与 ThreadStore | 原装 `codex-rs` / app-server |
| 最小特权桥 | preload |
| 用户界面和前端交互状态 | React renderer |
| 非 Responses 模型协议适配 | 可选 Gateway sidecar |

不得因为 UI 需要而修改 agent 内核；不得在 Electron main、renderer 或遗留 daemon 中重建 app-server 已提供的 thread、turn、工具、审批或持久化逻辑。

## “复刻 Codex App”的含义

允许：

- 研究公开文档与合法可观察的产品行为
- 对齐信息架构、工作流、反馈节奏和能力合同
- 对齐合法可观察的进程边界、Browser 生命周期、registry、隐藏运行、持久 profile、高层工具与 CDP 分层
- 使用自有实现、品牌、设计系统和宽松许可证依赖

不允许：

- 复制或反编译闭源代码、bundle 和协议密钥
- 提取并复用专有图标 path、字体或其他资源
- 暗示 BlackRain 是 OpenAI 官方客户端
- 用未验证的相似界面宣称功能一致
