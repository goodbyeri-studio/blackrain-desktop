# 04 产品形态

> **本文是产品形态的唯一真源。** 工作台/工作室/插件/技能的定义、各自 v1 状态、双入口映射,只在这里维护;其他文档(03 架构、.specs/003)不再重复定义,只链接到这里。
> 定型依据:2026-06-28 两轮采访(见 memory `2049-product-form-finalized-v1`)。

## 一、两个引擎 = 两个平级入口

2049 App 是一个壳,看管两个引擎,对用户呈现为**两个平级入口**:

| 入口 | 引擎 | 给谁 | 怎么做 |
|---|---|---|---|
| **WORK(办公)** | Hermes | 不写代码的办公小白 | 主战场,90% 产品设计精力,本文主要讲它 |
| **CODE(编码)** | codex | 会写代码的开发者 | **照抄 codex app**(汉化 + 国产模型 + 品牌),用 codex 原生词,不原创设计(见 §五) |

> **⚠️ 切分轴 = 受众 / UX,不是能力域(最易误读处,读到这里务必看清)**:
> **两个引擎都是完整、强大的 agent 内核,都能写代码。** Hermes(WORK)完全能写程序 / app / 小程序且做得强——WORK 侧小白直接说「帮我写个 app」,Hermes 自己就做,**不需要转去 CODE**。
> 上表「给谁」一列说的是**面向的人群**,**不是能力上限**:
> - **WORK** = 面向非开发者小白,在全能 agent 外**包护栏**;「工作台 / 工作室」是为照顾小白**额外加的易用层,不是能力天花板**。
> - **CODE** = 面向专业开发者,**不屏蔽复杂度**,给 codex 原生控制力与术语。
>
> 所以这不是「WORK 不能写代码、CODE 才能写」的能力筒仓——两边原始能力高度重叠,区分的是**两拨人、两种体验**。CODE 不是「WORK 缺的编码能力补给站」,而是给要 codex 裸控制的人的**另一种 UX**。

两个入口隔离,不强行打通。一个用户通常只在一个入口里。

## 二、WORK 侧的四个词(台阶:技能 → 插件 → 工作台 → 工作室)

这是整个产品最容易混的地方,这里一次定死。用厨房作尺子:

| 词 | 是什么 | 厨房类比 | v1 状态 |
|---|---|---|---|
| **技能(skill)** | 一段「怎么做一件事」的知识,纯 Markdown,不给新工具 | 菜谱 | 官方造,用户 v1 不造 |
| **插件** | 一个原子能力,对话里 `@` 一下就多一只手 | 一件厨具 | ✅ v1 暴露,小白能 `@` **官方**插件 |
| **工作台** | 一间布置好的房间:一组插件 + 技能 + 人设 + 环境 + 任务入口 | 配齐的厨房 | ✅ MVP 只做 **office 工作台**(通用办公:文档/表格/PPT/PDF);其他垂类(漫剧等)往后放 |
| **工作室** | 一人公司模式(OPC):多个工作台同时在场 | 一栋楼里多间厨房 | ⏳ 后期,v1 不做实体(仅 Pro 上限线) |

> **MVP 范围(2026-06-28)**:WORK 侧 MVP **只做 office 工作台**,不做垂类工作台——它最稳、最快、零生成成本,且 Hermes 现成 skill(powerpoint/ocr/office-docs/google-workspace)可白嫖。漫剧及其他垂类是 office 跑通后的下一步。CODE 侧 MVP = **复刻 codex-app**(GUI + 功能,基于 codex-rs)。双引擎一起上。

三条边界规则:
1. **技能 vs 插件**:技能只给知识(用 agent 已有的手),插件给一只新手(一个新能力)。
2. **插件 vs 工作台**:插件是散装积木(进阶玩家自己组合);工作台是布置好的成品房间(小白拎包入住,有人设、有任务按钮入口)。区分不是「轻/重」,是「裸能力 vs 成品岗位」。
3. **工作台 vs 工作室**:工作台 = 一间房;工作室 = 多间房同时开(OPC),v1 不做。

> 工作台/工作室是 **WORK 专属**;CODE 侧没有这两个概念(见 §五)。

## 三、工作台 —— 一间布置好的房间

小白点进一个工作台,看到的不是空白对话框,而是已经就位的工作空间。**MVP 出的是 office 工作台**:

```
🗂 办公工作台
─────────────────────────────────
你想做什么?
  ① 把这堆文件整理归档 / 批量改名
  ② 从 PDF / 扫描件里提取文字做成表格
  ③ 根据要点帮我写一份 PPT
  ④ 把这份 Word 按模板批量改格式
  ⑤ 自由提问
─────────────────────────────────
[ 当前文件夹:/我的文档/Q2汇报  共 23 个文件 ]
```

> 垂类工作台(后期)长一个样,只是换了人设和任务入口。例如番茄小说工作台:① 起爆款名 ② 看番茄热榜 ③ 规划新书大纲 ④ 续写章节。**MVP 不做垂类,只做上面的 office;番茄小说仅作「垂类工作台长啥样」的示意。**

> **MVP 任务入口的选择标准(2026-07-06 定)**:入口专挑**聊天类产品(豆包/Kimi/WPS AI)结构性做不了**的活——本地批量、跨文件、跨格式、多步长流程(「把 200 张发票扫描件变成一张台账」这种),不选单文档生成这类聊天框也能干的场景。**任务入口即定位**:用户对产品的第一认知就来自这几行字,必须在场景层面与免费巨头切割,而不是品类层面。选定的场景同时要在发布前完成端到端质量基线与「prompt→固化 skill」沉淀(见 §八与 [.specs/003 tasks](../.specs/003-dual-engine-architecture/tasks.md) 2026-07-06 重排)。

工作台 = 这些东西的集合(以 MVP 的 office 工作台为例):

| 构成 | 作用 | 技术形态 |
|---|---|---|
| 人设与规矩 | 「你是一个细致的办公助理,熟悉文档/表格/PPT 规范,动文件前先确认」 | 预置 AGENTS.md / 人设(纯文本) |
| 一组技能 | 文件整理、PDF 提取、PPT 生成、批量改格式…… | 若干 SKILL.md(纯 Markdown) |
| 一组插件 | 读写 Office 文档、OCR 识别、联网查资料 | @ 能力(MCP/工具) |
| 模板 | PPT 模板、汇报模板、表格模板 | 模板文件 |
| 铺好的工作目录 | 指向用户的文档文件夹 | 脚手架 |

**关键含义**:造一个工作台主要是写 Markdown 和配置,不是写代码——这让懂业务的人(而非程序员)也能造。但 **v1 只发官方工作台**,创作者自造留后期(见 [06](06-市场与创作者经济.md),整篇属后期)。

## 四、核心产品手艺:带护栏的发挥

这是整个产品最难、最值钱的设计题。**小白没有「发挥」能力**——对程序员「半成品 + 自己发挥」是自由,对小白容易变成「半成品 + 卡住 + 放弃」。

| 太开放 ❌ | 带护栏的发挥 ✅ | 太死板 ❌ |
|---|---|---|
| 给个对话框「你说需求我都能做」 | AI 自动铺好 90% 的路,关键岔路口给**选项** | 写死成固定表单 |
| 小白迷路、流失 | 用户只做有意义的决策,其余 AI 兜底 | 退化成普通 SaaS,丢掉 agent 杠杆 |

设计准则:① 入口是任务不是功能(「帮我做一份汇报 PPT」而非「调用 PPT 生成器」);② 岔路口给选项不要白纸(「这三种版式选哪个?」优于「请描述你想要的样式」);③ 默认值足够好(一路点「就这个」也像样);④ 进阶可接管(每步可切自由对话);⑤ 成果可视化(呈现 PPT 预览、表格、diff,不是命令行)。

> Hermes 原生的 `clarify` 工具(向用户提问、≤4 选项)就是「岔路口给选项」的现成原语,见 [.specs/003 hermes-capability-ledger](../.specs/003-dual-engine-architecture/hermes-capability-ledger.md)。

## 五、插件 —— 一个词,两侧两义(刻意,不是 bug)

「插件」在两个入口指的不是同一个东西,因为面对的是两拨人——这正是设计,不要强行统一:

- **WORK 侧插件** = 一个原子能力,小白在对话里 `@` 一下就多一只手(Coze 派语义,小白直觉)。v1 只能 @ 官方插件。
- **CODE 侧插件** = codex 原生的 `plugin`(打包 skills + MCP + apps + hooks 的分发单位,开发者熟)。

两个 surface、两拨人、各自自洽。

## 六、CODE 入口 —— 照抄 codex app

CODE 入口是给会写代码的开发者的,定调:**照抄 codex app,不原创设计。**

- 体验 = codex app 原貌(对话 + skill + codex 自带 plugin/marketplace),只做汉化 + 接国产模型 + 换品牌的强制改动。
- 用 **codex 原生词**(skill / plugin / AGENTS.md),不套小白化包装——开发者不需要被挡复杂度,挡反而碍事。
- **没有工作台、没有工作室**(那是 WORK 专属,给挡复杂度用的)。

为什么照抄而非差异化:codex 是**上游**不是竞争对手(美国的,不在中国非开发者市场抢人),照抄 = 技术跟进 = 免费 R&D。差异化只对真竞品(字节 Coze / 腾讯 WorkBuddy)打。详见 memory `2049-copy-upstream-differentiate-vs-competitors`。CODE 侧具体照抄到什么颗粒度,见 [.specs/003 codex-capability-ledger](../.specs/003-dual-engine-architecture/codex-capability-ledger.md)。

> **待决(2026-07-06)**:小白发行版是否默认隐藏 CODE 入口(收进高级设置)——「编码」入口对目标人群是「程序员工具」信号,与拆形态墙相悖;隐藏只影响首印象,不影响 CODE 能力存在。见 [.specs/003 decisions](../.specs/003-dual-engine-architecture/decisions.md) 2026-07-06 条。

## 七、让 AI 自己找食材

不需要把素材预先塞进产品——封面配图、参考资料、热榜数据,都由 agent 联网搜索/生成获得。WORK 侧 Hermes 原生带 `web_search`(免 key 兜底)、`image_generate`、`web_extract`,这个「素材获取」缺口在 WORK 侧基本白嫖补上(对比早先「自建关键缺口」的判断已松动)。

## 八、工作台成熟度路径(从「提示词」沉淀成「验证过的程序」)

「造工作台 = 写 Markdown」对规模化是命脉,但纯 prompt 拼的工作台没有确定性骨架,批量/多步任务跑到第 81 张图就会崩(单步 95% 准、20 步端到端只剩约 1/3,RPA 脆性)。所以成熟工作台顺这条路径沉淀,越靠后越可信:

```
① 纯 prompt 配方(创作者入口,低门槛,能跑通一次)
      ↓ 自用打磨,固化反复用的步骤
② prompt + 验证过的确定性 skill/脚本(把「临场推导」换成「跑验证过的程序」)
      ↓ 按垂类挂验证脚手架
③ + 验证脚手架(dry-run/diff/自检断言),交付时自证对错
```

赢得信任的工作台,底下是硬化过、能自检的执行件,不是一段提示词。「自己先用」天然就是这条沉淀路径的采集引擎。

> 正确性验证(给非专家证明输出对)是横切能力,按垂类伸缩力度(低=可视化+抽检 / 中=dry-run+diff / 高=自检断言+强制确认),详见 [07 护城河](07-护城河与风险.md) 护城河 D。
