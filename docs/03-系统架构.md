# 03 系统架构

## 结论

BlackRain 的目标架构是 **Electron 宿主 + React 界面 + Rust daemon + 原装 codex app-server**。Electron 提供桌面和 Browser 能力；Rust daemon 保留现有领域逻辑并监管内核；`codex-rs` 只负责 agent。

当前 HEAD 仍是 Tauri 实现。以下是目标分层，不是完成度声明。

## 目标拓扑

```text
BlackRain Electron
  ├─ Main process
  │   ├─ App/window lifecycle
  │   ├─ permission/download/update policy
  │   ├─ in-app browser WebContentsView
  │   └─ Rust daemon supervisor
  ├─ Preload bridge
  │   └─ typed allowlisted IPC
  ├─ React renderer
  │   ├─ projects / threads / composer
  │   ├─ approvals / diff / terminal
  │   └─ visible browser controls and state
  └─ blackrain_daemon
      ├─ shared domain cores
      ├─ original codex app-server
      ├─ dedicated CODEX_HOME
      └─ optional Model Gateway
```

## ① 原装 Codex 内核

- 来源：锁定的 OpenAI `codex-rs` 上游。
- 接口：`codex app-server` JSON-RPC 与事件流。
- 职责：thread、turn、工具调用、审批、停止、恢复和模型请求。
- 纪律：只读、只调用、不 fork agent loop、不叠加第二内核。

BlackRain 对内核的工作是版本锁、协议探针、能力盘点、构建和回归，不是改写。

## ② Rust daemon

daemon 是跨宿主的本地后端：

- 启停和监管 app-server
- 管理 App 专属 `CODEX_HOME`
- 提供项目、文件、Git、终端和已有 shared core
- 监管可选 Gateway
- 向 Electron main 提供鉴权 JSON-RPC
- 标准化事件和错误

迁移原则是把当前 Tauri App adapter 中可复用的逻辑收敛到 daemon/shared core，而不是迁入 Electron main。

## ③ Electron main 与 preload

Main 拥有所有桌面特权：

- BrowserWindow 与 WebContentsView
- 菜单、通知、剪贴板和外部协议
- 权限、下载、弹窗和导航策略
- daemon 生命周期、退出顺序和崩溃恢复
- 打包、签名、更新和系统集成

Preload 只暴露显式类型化 API。renderer 不获得 Node.js、原始 IPC、daemon token 或任意文件系统能力。

## ④ React renderer

React renderer 负责用户可见产品，不承担特权和领域真源：

- 项目与 thread 导航
- 对话、队列、审批和恢复
- diff、终端、工具活动和错误呈现
- Browser chrome、状态和用户接管
- 设置、账号和模型选择

现有设计系统和状态编排可以迁移；Tauri 调用必须逐步替换为宿主无关客户端合同。

## ⑤ In-app Browser

Browser 使用与 App renderer 隔离的 `WebContentsView`：

- 持久 partition 保存登录态
- 网页不加载 BlackRain preload
- Electron main 集中处理导航、权限、下载、弹窗和 CDP
- agent 与用户通过显式控制状态机交接
- 截图和下载作为受控 artifact 进入 thread/UI
- renderer 崩溃只影响对应 view，并可恢复

详细合同见 [spec 013](../.specs/013-codex-app-capability-parity/)。

## ⑥ Model Gateway

Gateway 只在目标模型不直接满足 codex Responses 合同时启用。它是独立 sidecar，负责协议翻译、流式事件、工具调用与错误映射；不拥有 thread、账号业务、Browser 或 UI 状态。

Gateway 不能成为第二 agent runtime，也不能改变 codex 的执行循环。

## 配置与凭据

- App 只写应用数据目录内的专属 `CODEX_HOME/config.toml`。
- 不读取或覆盖用户 `~/.codex`。
- provider secret 进入系统凭据存储。
- Browser Cookie 留在隔离 partition，不进入 thread、日志或模型上下文。
- daemon token、CDP 控制面和本地 RPC 不暴露到网络。

## 已暂停的层

工作台包、Session Orchestrator、插件市场、专家市场和 OPC 不属于当前运行时主链。相关目录和 specs 保留为冻结资产；P0 实现不得为它们新增并行 thread、surface 或配置写入路径。
