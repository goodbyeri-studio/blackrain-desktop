# 03 系统架构

## 结论

BlackRain 的目标架构是 **Electron/React 桌面协议客户端 + 原装 codex app-server**，直接对齐 Codex Desktop App 已确认的进程边界。Electron main 提供桌面能力并直接监管内核；`codex-rs` 负责 agent、工具、策略和 thread 持久化。当前 Rust daemon 属于 Tauri 迁移输入，不进入目标运行时。

当前 HEAD 仍是 Tauri 实现。以下是目标分层，不是完成度声明。

## 目标拓扑

```text
BlackRain Electron
  ├─ Main process
  │   ├─ App/window lifecycle
  │   ├─ App Server client / JSONL dispatcher
  │   ├─ permission/download/update policy
  │   ├─ Browser backend / WebContentsView registry / session / CDP
  │   └─ spawn bundled codex.exe app-server
  ├─ Preload bridge
  │   └─ typed allowlisted IPC
  ├─ React renderer
  │   ├─ projects / threads / composer
  │   ├─ approvals / diff / terminal
  │   └─ Browser sidebar controls / bounds / state
  ├─ bundled codex.exe app-server
  │   ├─ codex-core / ToolRouter / policy
  │   ├─ ThreadStore：rollout JSONL + SQLite
  │   └─ code-mode/MCP/sandbox helper processes
  └─ optional Model Gateway
```

## ① 原装 Codex 内核

- 来源：锁定的 OpenAI `codex-rs` 上游。
- 接口：`codex app-server` JSON-RPC 与事件流。
- 职责：thread、turn、工具调用、审批、停止、恢复和模型请求。
- 纪律：只读、只调用、不 fork agent loop、不叠加第二内核。

BlackRain 对内核的工作是版本锁、协议探针、能力盘点、构建和回归，不是改写。

## ② Electron main 与 App Server client

Main 拥有所有桌面特权：

- 以 `stdio: ["pipe", "pipe", "pipe"]` 启动 bundled `codex.exe -c features.code_mode_host=true app-server --analytics-default-enabled`
- stdin 写逐行 request/response/notification JSON，stdout 按 JSONL framing 解析，stderr 单独进入诊断流
- 管理 RPC id、双向 server request、thread 订阅、进程退出和协议错误
- BrowserWindow、WebContentsView、page WebContents、session、registry 与 CDP
- 菜单、通知、剪贴板和外部协议
- 权限、下载、弹窗和导航策略
- app-server 生命周期、退出顺序和崩溃恢复
- 打包、签名、更新和系统集成

App Server 协议具有 JSON-RPC request/response/notification 语义，但线上对象省略 `jsonrpc` 字段；main 不解析 TUI 字符输出，也不经 FFI、COM、DLL 或 localhost WebSocket 调用内核。

Preload 只暴露显式类型化 API。renderer 不获得 Node.js、原始 IPC、App Server transport 或任意文件系统能力。

## ③ React renderer

React renderer 负责用户可见产品，不承担特权和领域真源：

- 项目与 thread 导航
- 对话、队列、审批和恢复
- diff、终端、工具活动和错误呈现
- Browser chrome、状态和用户接管
- 设置、账号和模型选择

现有设计系统和状态编排可以迁移；Tauri 调用必须逐步替换为宿主无关客户端合同。

## ④ Codex 式 In-app Browser

BlackRain 高度采用四份本机 Browser 研究稿确认的 Codex App 功能与控制面，而不是建立独立 Playwright/headless agent browser。页面宿主保留有意差异：Codex 当前使用 renderer `<webview>` + main attach，BlackRain 使用由 main 直接持有的 `WebContentsView`。

```text
Codex thread / code-mode tool execution
  -> BlackRain Browser client
  -> authenticated per-session local transport
  -> Electron main BrowserBackend
  -> BrowserRegistry / BrowserViewManager
  -> main-owned WebContentsView
  -> page WebContents
  -> Electron API / Chromium CDP
```

main 创建每个 `WebContentsView`，在创建时固定 partition、sandbox、Node off、context isolation 和 web security，再把 view 加入 Browser registry。默认无 page preload；annotation/selection/capture 确有需要时，只允许 main 固定路径、固定 hash、无网页全局暴露的专用最小 preload。renderer 只通过类型化 IPC 上报 sidebar bounds、visibility、active tab、窗口 generation 和 modal/遮挡状态，不能创建页面 WebContents 或提供任意 partition、preload、CDP method。

main 维护以下不同标识，禁止混用：

```text
appSessionId -> ownerWindowId -> threadId/routeKey -> codexSessionId/turnId/backendGeneration
             -> browserTabId/apiTabId -> viewId/viewGeneration
             -> webContentsId -> targetId/debuggerSessionId
```

Browser 的关键合同：

- P0 使用 App 专属持久 partition `persist:blackrain-browser-app` 保存登录态。
- route/page ownership 与实际 storage partition 分离；所有 P0 页面共享受管持久 session，不把 route id 当成 Cookie 隔离边界。
- 网页不加载 BlackRain preload，不能看到 Node、IPC 或 App Server transport。
- 产品 UI 走 preload/main IPC；工具控制走按 Codex session 隔离、带 session/turn binding 的 Browser client/backend，两条链共享唯一 registry。
- 隐藏运行通过保留同一个 view/WebContents 并切换 visibility 或挂载关系实现，不复制第二套页面。
- tab 在窗口或 sidebar 间迁移时，由 main 从旧 `contentView` 移除并重新挂载到目标窗口；view generation 阻止旧布局消息控制新 owner。
- Electron main 集中处理导航、权限、下载、弹窗、输入注入和 CDP。
- agent 与用户通过显式状态机交接；用户可立即抢占。
- 高层 locator/CUA/snapshot API 默认开放；raw/full CDP 只在 Developer mode。
- locator/snapshot 将许可兼容的 selector、actionability 和增量 ARIA runtime 注入现有页面，不启动第二个 Playwright Chromium；OOPIF target 只在当前 route 内可见。
- `turn/completed`、中断和显式 finalize 按 agent/user、handoff、deliverable 规则关闭、保留或 release tab，并清理 debugger、cursor、capture 与 target session。
- detached live pages 使用可配置工作集、保护窗口、挂起和恢复；32 pages/30 分钟只作首个测量候选，Owl snapshot/adoption 不作为可复制依赖。
- 截图和下载作为有大小、来源和生命周期的受控 artifact 进入 thread/UI。
- renderer 崩溃不销毁 main-owned Browser view；页面 WebContents 崩溃只重建受影响 tab，保留 profile，并使旧 view generation 失效。
- React sidebar、modal、菜单和 tooltip 与 native view 的 bounds、z-order、遮挡和焦点策略必须通过 Windows 实机验证。

完整产品实施合同见 [10](10-Electron迁移与内置浏览器实现计划.md) 和 [002 Electron 全量迁移](../.specs/002-electron-migration/)；Browser 源码底座的去耦、adapter 和可移植性合同见 [003 可移植 Electron Browser Runtime](../.specs/003-portable-electron-browser-runtime/)。

## ⑤ 持久化与本地状态域

Codex 历史与结构化状态继续由原装 ThreadStore 管理：

- rollout JSONL 是规范 thread 历史日志，负责恢复、上下文重建、回放和 backfill。
- SQLite 承载可查询元数据、日志、goal、memory 等结构化状态，不能被 Electron 当作可任意删除的 UI cache。
- Electron 不直接改写 rollout 或 Codex SQLite；thread/start、resume、read、archive 等均走 app-server。
- 标准 Codex Home 保存 config/auth/thread，并与原生 CLI 共享；`app-state` 只保存窗口与 App 设置，`browser-data` 保存 Cookie、Cache、Service Worker 和 Browser profile。

## ⑥ Model Gateway

Gateway 只在目标模型不直接满足 codex Responses 合同时启用。它是独立 sidecar，负责协议翻译、流式事件、工具调用与错误映射；不拥有 thread、账号业务、Browser 或 UI 状态。

Gateway 不能成为第二 agent runtime，也不能改变 codex 的执行循环。

## 配置与凭据

- Electron App 默认不覆盖 `CODEX_HOME`，沿用 Codex 标准 Home 解析和父进程的显式选择。
- 其他自定义绝对路径只允许用户主动选择；BlackRain 不自动复制、合并或直接改写 Home。
- provider secret 进入系统凭据存储。
- Browser Cookie 留在 App 专属 partition，不进入 thread、日志或模型上下文。
- main/app-server 使用匿名子进程 stdio；Browser backend 和 CDP 不暴露到网络。

## 已暂停的层

工作台包、Session Orchestrator、插件市场、专家市场和 OPC 不属于当前运行时主链。相关目录和 specs 保留为冻结资产；P0 实现不得为它们新增并行 thread、surface 或配置写入路径。
