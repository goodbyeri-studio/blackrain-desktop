# 09 运行时架构与里程碑

> **本文是 Desktop 运行时与里程碑的唯一真源。** 产品优先级看 [04](04-产品形态.md)，整体迁移波次看 [10](10-Electron迁移与内置浏览器实现计划.md)，当前 P0 合同看 [002 Electron 全量迁移](../.specs/002-electron-migration/)。

> **状态（2026-08-03）**：Electron 全量迁移是唯一当前 P0。Browser runtime/功能链路已闭环并进入发布回归；当前完整产品仍由 Tauri 实现，Electron 开发签名 MSIX 可安装和 AUMID 首启但全页面不可点击。迁移基线为 194 个 Tauri command 和 59 个 renderer 直接依赖。

## 当前实现与目标态

| 层 | 当前实现 | 目标态 |
|---|---|---|
| 桌面宿主 | CodexMonitor 衍生 Tauri | Electron main/preload/renderer |
| UI | React/Vite | 复用并迁入 Electron renderer |
| 本地后端 | Tauri Rust App + Rust daemon/shared core | Electron main 内的 App Server client 与桌面宿主模块 |
| agent 内核 | 原装 codex app-server | 保持原装 codex app-server |
| Browser | Electron 迁移代码已有 main-owned `WebContentsView`、持久 session、registry、侧栏和受限 CDP foundation；尚未进入当前 Tauri 产品主流程 | Codex 功能对齐的 main-owned `WebContentsView`/session/registry/CDP |
| 模型适配 | Gateway 原型 | 按需独立 sidecar |
| 工作台/OPC | 部分资产和未完成合同 | 暂停，不在目标主链 |

目标态不能用来描述当前发布能力。

## 目标进程拓扑

```text
BlackRain Electron
  ├─ Main
  │   ├─ app/window/update lifecycle
  │   ├─ App Server client / JSONL dispatcher
  │   ├─ permission/download/navigation policy
  │   ├─ Browser backend/WebContentsView registry/session/CDP
  │   └─ spawn bundled codex.exe app-server
  ├─ Preload
  │   └─ typed allowlisted IPC
  ├─ React Renderer
  │   └─ projects/threads/approvals/diff/terminal/browser UI + bounds/state
  ├─ bundled codex.exe app-server
  │   ├─ codex-core / ToolRouter / policy
  │   ├─ standard Codex Home / ThreadStore
  │   └─ code-mode/MCP/sandbox helper processes
  └─ optional Model Gateway
```

## 唯一内核合同

1. 只有锁定的原装 `codex-rs` / app-server 执行 agent thread。
2. 不引入任何第二 agent runtime；Browser client、MCP 和 code-mode 等工具进程仍由同一个 app-server tool router 管理。
3. Electron、Browser 和 Gateway 只补宿主或适配能力，不拥有 agent loop。
4. thread、事件、审批、停止、恢复和模型路径只有一套真源。
5. 上游能力是否可用必须由当前锁定版本的探针与 E2E 证明。

## Electron 宿主

Main 负责窗口、权限、Browser、系统集成、更新和 app-server 生命周期，并直接持有 App Server client。Preload 提供最小类型化桥；renderer 无 Node.js 直通。当前迁移、安全和失败合同看 `002-electron-migration`。

Browser 页面不是 renderer 的例外能力。`WebContentsView` 只由 main 创建、挂载、隐藏、迁移和销毁；renderer 只上报经过 schema 校验的 bounds、visibility、active tab、窗口 generation 和 UI 遮挡状态。App renderer 与页面 WebContents 都保持 Node off，页面不加载 BlackRain preload。

迁移期允许当前 Tauri App 继续作为参照和开发入口，但不接受永久双宿主。每个兼容层必须有删除任务。

## App Server client 与协议

Electron main 直接启动 bundled `codex.exe`：

```text
codex.exe -c features.code_mode_host=true app-server --analytics-default-enabled
```

- `stdin`：main 写 request、response 和 notification。
- `stdout`：app-server 输出一行一个 JSON 对象的 JSONL；协议具有 JSON-RPC 2.0 语义但省略 `jsonrpc` 字段。
- `stderr`：只作日志与诊断，不与协议帧混用。
- 协议双向：app-server 可以向 main 发 approval、elicitation 和其他 server request，main 必须关联 id 返回 response。
- main 管理 pending request、超时、取消、未知消息、子进程退出和重连后的旧 request 失效。

标准生命周期是 `initialize -> initialized -> thread/start|resume -> turn/start -> item/delta/completed -> turn/completed -> thread/unsubscribe|process exit`。Thread、Turn、Item 与 v2 notification 是 app-server 对 Core event 的产品化投影；Electron 不解析 TUI 输出，也不重新映射裸 Core event。

当前 `blackrain_daemon`、固定 `127.0.0.1:4732` 和 remote backend 只属于 Tauri 迁移起点。目标 Electron 不保留 daemon 中间层或固定本地网络入口。

## In-app Browser

Browser 高度对齐本机研究确认的 Codex App 功能与控制面，同时使用 main-owned `WebContentsView` 代替 Codex 当前观察到的 renderer `<webview>`：

```text
app-server / codex-core tool execution
  -> 标准 stdio MCP
  -> BlackRain Node Browser adapter
  -> BlackRain Browser client
  -> authenticated per-session local transport
  -> main BrowserBackend
  -> session registry / sidebar manager
  -> main-owned WebContentsView
  -> page WebContents
  -> Electron API / Chromium CDP
```

- main 在创建、布局、迁移和每次工具调用时校验 owner window、thread、route、view generation 和 profile。
- P0 使用单一 App 专属持久 partition，保持跨 thread/App restart 登录态。
- 每个 Codex session 建立独立 backend route，请求绑定 session、turn、backend generation 和页面 ownership；产品 UI IPC 与工具 transport 不共享权限面。
- 隐藏或侧边栏切换时保留同一个 view/WebContents；隐藏活动仍须在 thread 中可观察和停止。
- tab 迁移通过 main 在窗口 `contentView` 之间重新挂载同一 view，不序列化 Cookie 或重建旁路页面。
- main 集中处理导航、弹窗、权限、一次性 download grant、输入注入和 CDP。
- agent/user 控制权显式转换，用户输入可以立即抢占 agent。
- 默认工具是高层 tabs/locator/CUA/snapshot/artifact API；full CDP 只在 Developer mode。
- selector/actionability/增量 ARIA runtime 注入现有页面 target，不启动独立 Playwright browser；跨进程 iframe 使用 route-scoped debugger session。
- turn 完成和显式 finalize 按 origin/handoff/deliverable 收口 tab，并清理 debugger、cursor、capture surface 与 target session。
- 多 tab 采用 live/suspended/persisted 工作集；观察到的 32 pages/30 分钟保护窗口只作首个候选。标准 Electron 的最低恢复合同是 tab/route、URL、可获得的 navigation entries 和持久 session 后 reload，不承诺私有 Owl snapshot、JS heap、未提交表单或滚动位置。
- 网页与 App renderer 权限隔离；Cookie、Local Storage、认证 token、密码和下载正文不被自动写入 thread 或日志，显式 snapshot/截图的可见内容按 Browser 工具合同进入模型。
- React 侧边栏通过类型化 IPC 同步 bounds；modal、菜单、tooltip、DPI、多屏、焦点和输入法属于发布验收项。

BlackRain 不复制 Codex 的私有 `node_repl.exe`、`browser-client.mjs`、`nativePipe` 或 Owl 扩展。dynamic tools 只作测试/bootstrap；生产链路使用标准 stdio MCP、随包 Node 22 adapter、自有 Browser client、随机 endpoint、仅目标用户/系统 ACL、capability token 和有界 framed JSON-RPC，并且仍落到同一个 Browser backend。

2026-07-31 的锁定 Windows runtime 实制品探针确认 code-mode V8 不能 import Node/文件模块，但这不是 Browser client 的生产加载层。后续 bundled `0.146.0` 探针已验证进程级 MCP 配置、MCP ready/tool discovery、`mcpServer/tool/call`、codex-core 可信 `_meta` 透传和同一 backend 命中；P0-B1 的接缝阻塞已解除。正式包携带并校验 Node.js `22.23.2`、MIT License、MCP adapter 和 Browser client，Electron `RunAsNode` fuse 继续关闭。

自有 transport 不与 OpenAI 私有 pipe 互操作。4-byte little-endian 长度和 8 MiB 上限只是 BlackRain v1 的有界解析选择。ACL 证明 Windows 用户边界，token 证明调用者持有当前 capability；不声称隔离能够读取同用户进程内存、句柄或环境的恶意代码。

当前产品验收见 `002-electron-migration`。

## 配置、持久化与 Gateway

- Electron App 默认不覆盖 `CODEX_HOME`，沿用 Codex 标准 Home 解析，与 CLI 共享 config、auth、sessions、skills、plugins、rollout 与 SQLite。
- `%APPDATA%\BlackRain` 只保存 `browser-data`、`app-state`、`logs`、`artifacts` 等宿主状态，不创建第二个隐藏 Codex 状态域。
- 其他自定义绝对 Home 只作为用户主动选择的模式；BlackRain 不自动复制、合并或直接改写 Home。
- bundled `codex.exe` 路径独立于 Codex Home；使用 App 自带二进制不会把用户状态迁入安装目录或 BlackRain app-data。
- rollout JSONL 是规范 thread 历史；SQLite 是查询/元数据投影及日志、goal、memory 等结构化状态。Electron 只通过 app-server 操作，不直接改写两者。
- Electron/Chromium user-data 独立保存 Cookie、Cache、Service Worker、Crashpad 和窗口/Web 状态，不与 Codex Home 混为一体。
- provider secret 与 credit JWT 规范副本存入系统凭据存储；Gateway 短期 JWT 文件桥只进入 BlackRain app-data，并在停止或登出时清理。
- 原生 Responses provider 直接连接；不兼容时使用独立 Gateway。
- BlackRain 专属 Gateway provider/model 使用 app-server 进程级 `-c` override，不持久写入共享 `config.toml`。
- Gateway 只做协议翻译，不处理 Browser 数据或产品状态。

## Windows 制品目标

最终 Windows 安装包包含：

- Electron Desktop 及必要 Chromium 资源
- 锁定的 codex Windows x64 二进制
- 锁定版本要求的 `codex-code-mode-host.exe`、`codex-command-runner.exe` 等 helper
- 锁定的 Node 22 Windows x64 runtime、BlackRain Browser MCP adapter/client 及其 License/manifest
- 可选 Gateway 运行资源
- License、NOTICE、更新和诊断资源

Windows MVP 对齐已观察的 Codex App 工程：npm、Electron Forge、Vite、TypeScript 与 MSIX maker。M1 已锁定 Electron `42.3.0`、Forge `7.11.1`、Vite `8.1.3`、TypeScript `5.9.3`、React `19.2.5`；Windows 本机与 CI 已生成 unsigned MSIX，但 dev toolchain 传递漏洞、签名和 MSIX 安装/升级/卸载实机验收仍未收口。旧 Tauri NSIS 和此前 `electron-builder` 方向均不再是目标发布方案。

## Browser 回归基线

1. 真实 Codex turn 通过唯一生产 adapter 操作用户看到的同一个页面，不存在旁路 headless browser。
2. 登录、接管、locator/CUA、截图、下载、权限和恢复通过 Windows 真实场景。
3. renderer、网页、其他 thread、旧 generation、其他 Windows 用户和未持有当前 capability token 的同用户进程不能越权控制 Browser backend；威胁模型边界已明确记录。
4. Browser client/backend、page/App/app-server 异常恢复和资源清理通过。
5. 历史证据保留在 Git 中；当前发布回归结果写入 `002-electron-migration/verification.md`。

## Electron 全量发布判定

只有同时满足以下条件，才能声称 Electron 版本可交付：

1. 真实 Codex thread、审批、停止和恢复通过。
2. in-app browser 的登录、接管、下载、权限和崩溃恢复通过。
3. 真实 Codex thread 能通过受控 Browser 工具操作用户看到的同一个页面 WebContents，不存在旁路 headless browser。
4. Windows 安装、首启、升级、回滚和卸载通过。
5. renderer/preload/main/app-server/browser 权限审计通过，网页和未授权 renderer 不能调用 Browser backend 或 App Server transport。
6. 性能和资源基线在目标设备上可接受。
7. 对应 `verification.md` 记录具体日期、制品和证据。
