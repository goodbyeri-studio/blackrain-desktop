# 09 运行时架构与里程碑

> **本文是 Desktop 运行时与里程碑的唯一真源。** 产品优先级看 [04](04-产品形态.md)，具体实现看 [spec 012](../.specs/012-electron-shell-migration/) 和 [spec 013](../.specs/013-codex-app-capability-parity/)。

## 当前实现与目标态

| 层 | 当前实现 | 目标态 |
|---|---|---|
| 桌面宿主 | CodexMonitor 衍生 Tauri | Electron main/preload/renderer |
| UI | React/Vite | 复用并迁入 Electron renderer |
| 本地后端 | Tauri Rust App + Rust daemon/shared core | Rust daemon/shared core |
| agent 内核 | 原装 codex app-server | 保持原装 codex app-server |
| Browser | 未实现产品级 in-app browser | 隔离的 WebContentsView/session |
| 模型适配 | Gateway 原型 | 按需独立 sidecar |
| 工作台/OPC | 部分资产和未完成合同 | 暂停，不在目标主链 |

目标态不能用来描述当前发布能力。

## 目标进程拓扑

```text
BlackRain Electron
  ├─ Main
  │   ├─ app/window/update lifecycle
  │   ├─ permission/download/navigation policy
  │   ├─ Browser WebContentsView/session/CDP
  │   └─ Rust daemon supervisor
  ├─ Preload
  │   └─ typed allowlisted IPC
  ├─ React Renderer
  │   └─ projects/threads/approvals/diff/terminal/browser UI
  └─ blackrain_daemon
      ├─ shared domain cores
      ├─ original codex app-server
      │   └─ dedicated CODEX_HOME/config.toml
      └─ optional Model Gateway
```

## 唯一内核合同

1. 只有锁定的原装 `codex-rs` / app-server 执行 agent thread。
2. 不引入任何第二 runtime。
3. Electron、Browser 和 Gateway 只补宿主或适配能力，不拥有 agent loop。
4. thread、事件、审批、停止、恢复和模型路径只有一套真源。
5. 上游能力是否可用必须由当前锁定版本的探针与 E2E 证明。

## Electron 宿主

Main 负责窗口、权限、Browser、系统集成、更新和 daemon 生命周期。Preload 提供最小类型化桥；renderer 无 Node.js 直通。详细安全、失败与迁移合同看 spec 012。

迁移期允许当前 Tauri App 继续作为参照和开发入口，但不接受永久双宿主。每个兼容层必须有删除任务。

## Rust daemon

daemon 是 Electron 与 codex 之间的本地后端：

- 监管 app-server 和可选 Gateway
- 管理专属 `CODEX_HOME`
- 承载项目、文件、Git、终端等 shared domain core
- 统一 JSON-RPC、事件、错误和退出恢复

Electron main 不重写这些领域逻辑；renderer 不直接访问 daemon token。

## In-app Browser

Browser 使用独立 webContents 和持久 partition：

- 网页与 App renderer 权限隔离
- main 集中处理导航、弹窗、权限、下载和 CDP
- agent/user 控制权显式转换
- 可观察、可停止、可截图、可恢复
- Cookie 与网页 secret 不默认进入 thread 或日志

第一项产品验收见 spec 013。

## 配置与 Gateway

- App 是专属 `CODEX_HOME/config.toml` 的唯一写入者。
- 用户 `~/.codex` 不参与。
- provider secret 存入系统凭据存储。
- 原生 Responses provider 直接连接；不兼容时使用独立 Gateway。
- Gateway 只做协议翻译，不处理 Browser 数据或产品状态。

## Windows 制品目标

最终 Windows 安装包包含：

- Electron Desktop 及必要 Chromium 资源
- Rust daemon
- 锁定的 codex Windows x64 二进制
- 可选 Gateway 运行资源
- 专属 `CODEX_HOME` 模板
- License、NOTICE、更新和诊断资源

具体打包、签名和更新方案尚未决策。旧 Tauri NSIS 配置不能自动作为 Electron 发布方案。

## 发布判定

只有同时满足以下条件，才能声称 Electron 版本可交付：

1. 真实 Codex thread、审批、停止和恢复通过。
2. in-app browser 的登录、接管、下载、权限和崩溃恢复通过。
3. Windows 安装、首启、升级、回滚和卸载通过。
4. renderer/main/daemon/browser 权限审计通过。
5. 性能和资源基线在目标设备上可接受。
6. 对应 `verification.md` 记录具体日期、制品和证据。
