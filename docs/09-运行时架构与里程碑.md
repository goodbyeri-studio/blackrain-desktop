# 运行时架构与里程碑

> 本文是 Desktop 运行时边界的唯一真源。产品形态见 [04](04-产品形态.md)，工作台包协议见 [spec 008](../.specs/008-expert-workbench-package/)，当前完成度以代码和各 spec 的 `verification.md` 为准。

## 进程拓扑

```text
BlackRain Desktop（Tauri）
  ├─ Workbench Core
  │   ├─ Manifest 检查
  │   ├─ 依赖与权限验证
  │   ├─ 安装与 smoke
  │   └─ 激活记录与卸载
  ├─ Session Orchestrator
  │   └─ 激活记录 + 项目 + 任务 -> 受控会话描述符
  ├─ Workbench surface / CODE surface
  │   └─ 共享 thread、事件、审批、恢复和成果合同
  ├─ codex app-server（唯一 agent 子进程，原装黑盒）
  │   └─ 读取 App data/CODEX_HOME/config.toml
  └─ Model Gateway（独立 sidecar）
      └─ Responses -> Chat Completions -> new-api -> 模型提供商
```

Desktop 管理本地项目、工作台状态、会话编排、codex 子进程和模型网关。普通工作台不拥有独立任务进程：Session Orchestrator 按 [spec 011](../.specs/011-workbench-session-orchestration/) 将 spec 008 的已验证激活记录转换为同一 codex 运行时的受控会话。

## 配置边界

App 是唯一配置写入者：

- codex 读取应用数据目录内的专属 `CODEX_HOME/config.toml`。
- 用户已有的 `~/.codex` 不读取、不覆盖。
- 工作台包只能声明期望状态，不能写引擎配置或全局环境。
- provider secret 进入系统凭据存储，不进入 Manifest、激活记录或日志。

## Gateway

上游 codex 只发 Responses 协议；目标模型链路使用 Chat Completions，因此 Gateway 是所有 codex 模型会话的硬依赖。

Gateway 服务全部 codex 模型会话，并保持独立进程：

- 崩溃不拖垮 UI。
- 协议变更不污染工作台层。
- 可以从 Python 原型替换为其他实现而不改变上层合同。
- 工具调用、流式事件和错误映射必须有回归测试。

## 工作台 Core

当前职责仅限：

1. 严格解析 Manifest。
2. 校验平台、依赖、来源、校验和、License 和权限。
3. 在 App data 中 staging 并执行 health/smoke。
4. 全部通过后原子持久化激活记录。
5. 卸载时移除激活记录并保留用户项目。

Workbench Core 不启动 thread、生成 prompt 或维护事件。激活后的执行属于 Session Orchestrator：它只能读取并重新校验激活记录，生成不可变会话描述符，通过 shared codex core 启动或恢复 thread；它不能修改工作台包或成为第二配置写入者。

## 会话与 surface

- `workbench` surface 面向普通用户，围绕任务、审批、进度、工具活动、成果和异常组织。
- `code` surface 面向开发者，保留 diff、终端、分支和高级控制。
- 两者共享同一 codex thread、标准化事件、审批、停止、恢复、Gateway 和计量合同。
- surface 是呈现策略，不是进程或内核选择器。
- 当前 CODE surface 已有代码；Session Orchestrator 和工作台 surface 尚未实现，不能由目标拓扑推断为可用。

## 制品

Windows 安装包目标包含：

- Tauri Desktop
- codex Windows x64 二进制
- Gateway 运行资源
- 默认工作台与插件资源
- OfficeCLI 等经审计的应用托管依赖
- 专属 `CODEX_HOME` 模板

v1 不依赖用户预装 codex、Node 或开发工具。源码锁定不等于制品已通过 Windows 产品验收。

## 里程碑

| 里程碑 | 范围 | 状态 |
|---|---|---|
| R1 | CODE 壳、app-server 接缝、专属配置 | 代码存在，Windows 真对话待验 |
| R2 | Responses 转换 Gateway 与 new-api | 原型存在，生产工具链待补 |
| R3 | 工作台 Manifest、Office 安装事务、激活记录 | 代码存在，Windows 实机待验 |
| R4 | Session Orchestrator、工作台 surface、统一恢复与审批 | 合同已定义，代码未实现 |
| R5 | NSIS、Credential Manager、安装/升级/卸载矩阵 | 未完成 |
| R6 | Office 真实任务 E2E 与领域质量基线 | 未完成 |

发布状态不得由目标拓扑或非 Windows 检查推断，必须引用 spec 007 和对应功能 verification。
