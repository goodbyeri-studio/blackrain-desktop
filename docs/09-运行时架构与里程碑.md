# 09 运行时架构与里程碑

> 本文是 [03 系统架构](03-系统架构.md) 的运行时落地版：03 讲"分几层、复用什么"，本文讲"跑起来时有几个进程、谁管谁、怎么换挡"。

## 一句话

桌面 App 是一个**监工**，看管两个长期运行的小弟——codex 内核（干活）和模型网关（翻译）；App 自己是**唯一写配置的人**，所有"接国产模型"的脏活锁在网关进程里，内核保持原装不动。

## 运行时拓扑

```
┌─ 2049 App（fork 自 CodexMonitor，Tauri）─────────────────┐
│                                                          │
│  前端：对话 / diff / 审批 / Providers面板 / 工作台          │
│       ↕                                                  │
│  Rust 后端 = 监工 + 唯一写配置的人                         │
│       ├─ 拉起看管 → codex 内核（子进程·黑盒·原装）          │
│       │                └─读 config.toml 后 HTTP 调模型 ↓   │
│       └─ 拉起看管 → 模型网关（子进程·仅接国产时才起）        │
│                         └─ responses⇄chat 翻译 → HTTP ↓    │
└────────────────────────────────────────────│─────────────┘
                                              ↓
                            DeepSeek / GLM / Qwen / Kimi ...
```

配置是单行道：**Providers 面板（唯一写入）→ 专属 config.toml → 内核读取 → base_url 决定连官方还是连网关。**

## 三条铁律

1. **内核永远原装，谁都别改。** 接国产、防协议废弃、品牌，没一件需要动 agent 循环。能不改就永远白嫖上游更新——这是"忠于上游"卖点的物理保证。
2. **最难的活（responses⇄chat 翻译）锁进可替换的小弟进程。** 它崩不拖垮界面；它最常改（国产 API 老变）不碰别人；今天 ccNexus 明天换自研 Rust 版，上层架构零改动。
3. **App 是唯一写配置的人，且用专属 CODEX_HOME。** 藏在 app 数据目录，绝不碰用户机器原有 `~/.codex`。既不和已装 codex 打架，也消除"Providers 面板 vs 上游抢 config.toml"——两个写入方都是 fork 内自己的代码，协调即可。详见 [08](08-仓库结构与上游策略.md)。

## 内核形态：钉死+自带黑盒（不是 PATH 黑盒）

"黑盒"是两根轴：**行为**（改不改 agent 循环）+ **制品**（二进制从哪来）。

| 形态 | 行为 | 制品 | 用于 |
|---|---|---|---|
| PATH 黑盒 | 不改 | 用用户机器上的 `codex`（CodexMonitor 现状） | 玩具 ❌ |
| **钉死+自带黑盒** | 不改 | 从钉死的 upstream commit 构建、打包进 app | **v1 ✅** |
| 最小 fork 黑盒 | 仍不改循环，只 patch 品牌/去登录/去遥测/国产默认 | 从 fork 分支构建 | B2B 合规触发时 |
| 硬 fork | 大改 | 自养 97 crate | 永远别 |

v1 行为上当黑盒成立（接国产在壳外解决），但**制品轴必须升级**：钉版本（可复现、自主决定何时吃上游）、供应链可控、随 app 打包。离开黑盒的唯一现实触发点 = B2B 要"可证明零外联"或白标，那时升到**最小 fork**，agent 循环一行不动。

## 换挡 = 改配置，不是重构

03 文档的 A 阶段（`wire_api=chat` 直连）→ B 阶段（上翻译网关），在本架构里**不是两套架构，是同一套里 base_url 指向的变化**：

- **v1**：`wire_api=chat`，base_url 直指 DeepSeek，**网关槽位为空**，codex 原生即可连，最快跑通。
- **协议废弃 / 需 responses 独有功能时**：把网关小弟塞进空槽，base_url 改指它。界面、内核、结构全不变，只多一跳。

好架构的标志：升级改的是配置，不是推倒重来。现在不必为没发生的废弃提前造网关，但位置已留好。

## 里程碑

| 里程碑 | 目标 | 验证 |
|---|---|---|
| **M0** | 壳能 build、拉起内核、官方模型对话 | 底盘活着 |
| **M1** | Providers 面板 + 专属 CODEX_HOME，`wire_api=chat` 直连 | **DeepSeek 跑通**（网关槽仍空）|
| **M2** | 工作台/插件（往 CODEX_HOME 放 skills/AGENTS.md + 管理界面）| 小白能用一个垂类工作台 |
| **M3** | 网关填实（协议废弃时）、沙箱、市场 | 按需推进 |

对应目录：`apps/desktop`（监工+界面）/ `gateway`（可替换小弟的槽）/ `plugins`（放进 CODEX_HOME 的文件）/ `codex-upstream`（原装内核）。
