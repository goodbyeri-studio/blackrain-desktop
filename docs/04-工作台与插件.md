# 04 工作台与插件

> 这是 2049 App 最核心、也最体现产品手艺的两个概念。它们决定了「普通人能不能用」和「平台能不能规模化」。

## 概念层级

```
技能 / 插件(乐高积木)
      ↓ 组合 + 环境 + 人设
工作台(布置好的一个完整岗位)
      ↓ 汇集
市场(注册表,人人可上传)
```

- **技能(Skill)**:最小能力单元。完成一件具体小事,如「给小说起爆款名」「分析番茄热榜」。技术上 = 一个目录 + 一份 `SKILL.md`(纯 Markdown)。
- **插件(Plugin)**:面向进阶玩家的能力包,= 一个 skill / 一个 MCP server / 一个 connector。拿到手即获得某项能力,之后凭个人发挥组合。
- **工作台(Workbench)**:面向小白的核心交付物。一间别人预先布置好框架、环境、工具的房间。

### 粒度三层铁律(别把任务做成插件)

用 OS 心智模型(底座=内核、插件=apt 包、工作台=项目、配方=脚本)一句话定死三层各自的边界:

| 层 | 是什么 | 数量级 | 切分依据 |
|---|---|---|---|
| **插件** | 一个引擎/格式适配器 + 原生操作族 = 一个 MCP server = 一个 `@` | ~34 稳定 | 按「运行时 + license」切 |
| **skill 配方** | 任务级组合(转竖屏、改图框、出门窗表、周报),纯 Markdown | 数百 | 按「任务」铺 |
| **工作台** | 插件 + 配方 + 环境模板,装进一个本地项目 | 按垂类 | 按「岗位」装 |

> 铁律:**没人 `apt install 把视频转竖屏`——只装 `ffmpeg`(插件),再用脚本(配方)组合它。** 想加覆盖面先加配方(近零成本),只有冒出新引擎/新格式时才加插件。完整插件目录(7 浏览类 × ~34 单元、各包 license 与 [铺]/[控])见 [.specs/004-plugin-catalog](../.specs/004-plugin-catalog/)。

## 工作台:一间布置好的房间

### 用「番茄小说工作台」举例

小白点进去后,看到的不是一个空白对话框,而是一个已经就位的工作空间:

```
📕 番茄小说工作台
─────────────────────────────────
你想做什么?
  ① 给我的小说起一个爆款名字
  ② 看看番茄今天的实时热度榜
  ③ 根据热门题材,帮我规划一部新书大纲
  ④ 续写 / 扩写我的章节
  ⑤ 自由提问
─────────────────────────────────
[ 我的作品：《xxx》  上次写到第 12 章 ]
```

点「③ 规划新书大纲」,agent 会:联网拉取番茄实时榜单 → 分析当下热门题材和套路 → 结合用户偏好生成几个选题方向(给**选项**,而非要用户描述需求)→ 用户选定后展开人物设定、世界观、分卷大纲 → 落成本地文档。

### 工作台 = 什么的集合

| 构成 | 作用 | 技术形态 |
|---|---|---|
| **人设与规矩** | 「你是一个资深网文编辑,熟悉番茄的爽点节奏和审核红线」 | 预置 `AGENTS.md`(纯文本) |
| **一组技能** | 起名、看榜、规划、续写…… | 若干 `SKILL.md`(纯 Markdown) |
| **数据源 / 工具** | 联网搜榜单、生成封面插画 | MCP connector |
| **模板** | 大纲模板、人物卡模板 | 模板文件 |
| **铺好的工作目录** | 作品文件夹结构已建好 | 脚手架 |
| **验证脚手架** | 「这 80 张图改完，给你一份 diff 清单逐张核」「账不平就拦住不交付」 | 按垂类伸缩的自检/预览(见下） |

**关键含义**:造一个工作台,主要是写 Markdown 和配置,而**不是写代码**。这让懂业务的网文编辑、会计自己就能造工作台——这是平台能规模化的命脉。

## 核心产品手艺:带护栏的发挥

这是整个产品最难、也最值钱的设计题。

> **小白没有「发挥」能力。** 对程序员,「半成品 + 自己发挥」是自由;对小白,很容易变成「半成品 + 卡住 + 放弃」。

工作台必须在两个极端之间找到平衡:

| 太开放 ❌ | 带护栏的发挥 ✅ | 太死板 ❌ |
|---|---|---|
| 给个对话框「你说需求我都能做」 | AI 自动铺好 90% 的路,关键岔路口给**选项** | 写死成固定流程的表单 |
| 小白迷路、不知道能干嘛、流失 | 用户只做有意义的决策,其余 AI 兜底 | 退化成普通 SaaS,丢掉 agent 随机应变的杠杆 |

**设计准则**:
1. **入口是任务,不是功能**:展示「帮我规划一部新书」,而不是「调用大纲生成器」。
2. **岔路口给选项,不要白纸**:「这三个选题方向你选哪个?」优于「请描述你想写什么」。
3. **默认值要足够好**:小白一路点「就这个吧」也能得到像样结果。
4. **进阶可以接管**:每一步都允许用户切到自由对话深度定制,不被护栏锁死。
5. **成果可视化**:呈现封面、大纲文档、对账表,而非命令行日志。
6. **成果可验证(≠ 可视化)**:可视化只让人「看得懂」,可验证要让非专家「信得过」。把对账表渲染得漂亮,不等于证明里面数字对。按垂类伸缩:网文/媒体看一眼即可;数据/图纸给 dry-run + diff 让用户逐项核;财务/报送跑引擎自检断言(账平/借贷相等/schema),不过就拦住交付。这是护城河 D,详见 [03 系统架构](03-系统架构.md) ④验证层、[07 护城河](07-护城河与风险.md)。

## 插件:给进阶玩家的自由

插件面向爱折腾、懂一点的用户。一个插件 = 完成某目的的全套必需品,拿到手后凭个人发挥:

- 形态:单个 skill、MCP server、或 connector。
- 用法:在自由对话里 `@` 调用,或组合进自己的流程。
- 与工作台的关系:工作台是「插件 + 环境 + 人设」打包好的成品房间;插件是散装积木。进阶玩家用积木,小白用房间。

## 「让 AI 自己找食材」

用户洞察:不需要把素材预先塞进产品,**食材让 AI 上网找**。例如网文工作台需要的封面配图、参考资料、热榜数据,都由 agent 联网搜索/生成获得。

⚠️ **这是一个需要自建的关键缺口**:Codex 本身没有一等公民的「素材下载/生成」工具——它能下载素材的前提是「命令执行 + 网络访问 + MCP/skill」的组合。所以我们要为常见素材需求(搜图、生图、生视频、扒公开数据)封装好开箱即用的技能。详见 [03 系统架构](03-系统架构.md) 的「自建 vs 复用」表。

## 工作台的生命周期

```
创作者造(写 Markdown + 配置)
   → 自己用(single-player,先对自己有用)
   → 打磨到惊艳
   → 上架市场
   → 小白点开即用
   → 反馈/数据回流,迭代
```

注意「自己先用」这一步:它既是质量保证(没打磨到自己爱用,不会上架),也是冷启动的解法(自用沉淀的好东西顺手变成市场供给)。详见 [06 市场与创作者经济](06-市场与创作者经济.md)。

## 工作台成熟度路径:从「提示词」沉淀成「验证过的程序」

「造工作台 = 写 Markdown」对**创作者规模化**是命脉,但对**执行可靠**是另一面:纯 prompt 拼出来的工作台没有确定性骨架,每次运行都从自然语言**临场重新推导**怎么干——批量/多步任务跑到第 81 张图、第 5000 行就会崩(单步 95% 准、20 步端到端只剩约 1/3)。这正是 RPA 脆性,且比 RPA 更糟(RPA 至少录了段确定回放)。

所以成熟工作台要顺着这条路径沉淀,**越靠后越可信、越能泛化**:

```
① 纯 prompt 配方(创作者入口,低门槛,能跑通一次)
      ↓ 自用打磨,把反复用的步骤固化
② prompt + 验证过的确定性 skill/脚本(把「临场推导」换成「跑验证过的程序」)
      ↓ 按垂类挂上验证脚手架
③ + 验证脚手架(dry-run/diff/自检断言),交付时自证对错
```

- **Markdown 是创作者进门的低门槛;但赢得信任的工作台,底下是硬化过、能自检的执行件。**
- 沉淀物应是**一段验证过的程序**,不是一段提示词——这也是「工作完成优先」相对 RPA「流程编辑器优先」的真正质量差(见 [07 护城河](07-护城河与风险.md))。
- 「自己先用」这一步天然就是这条沉淀路径的采集引擎:每跑一次真活,就有机会把它从 ① 推向 ③。
