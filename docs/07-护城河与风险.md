# 07 护城河与风险

## 护城河

BlackRain 不拥有 `codex-rs`，也不能靠“用了 Electron”形成壁垒。真正可积累的是：

### 上游吸收能力

- 精确锁定和构建 codex 上游
- 版本化 app-server 能力矩阵
- 协议漂移探针和回归测试
- 把新内核能力快速变成稳定 UI
- 不依赖长期 fork 的升级纪律

### 桌面宿主能力

- Browser、权限、下载、更新和系统集成
- agent 与用户接管同一 surface 的状态机
- app-server、renderer 和 browser renderer 的独立恢复
- Windows 安装、签名、更新和诊断

### 产品完成度

- thread、diff、审批、终端、Browser 的一致工作流
- 错误、等待、取消、恢复和离线状态的可理解反馈
- 长时间运行的稳定性、性能和可访问性
- 能力声明与真实验证证据绑定

这些能力单项都可复制，持续跟随上游并把它们组合成可靠产品才是积累。

## 风险 1：把复刻误解为复制

观察产品行为不授权复制闭源实现。不得提取 OpenAI 私有 bundle、代码、图标 path、字体、协议凭据或受限制资源。

应对：只用公开资料和合法观察定义用户合同；代码、品牌、资源和设计系统全部自有或来自可用许可证。

## 风险 2：目标态冒充当前实现

仓库当前仍是 Tauri。只改文档或建立 Electron 空壳都不等于迁移完成；`WebContentsView` 存在也不等于 Browser 可交付。

应对：严格区分 designed、code-exists、verified 和 release-ready，结论引用 `verification.md`。

## 风险 3：形成 Tauri/Electron 永久双宿主

如果每项能力都维护两套 adapter、事件和测试，迁移会变成长期分叉。

应对：先按 Codex App 分层建立 Electron main App Server client，再按能力簇迁移现有 Tauri surface；Rust daemon 和兼容层必须有删除任务和最终闸口。

## 风险 4：Electron 权限面扩大

renderer、网页、preload、main 和 app-server 任一边界过宽，都可能把网页内容变成系统权限入口。

应对：Browser 页面只由 main 创建，强制 `contextIsolation`、sandbox、`nodeIntegration: false`、独立 partition、默认拒绝权限和集中外部协议策略。页面不得加载 App preload；确需 annotation/selection/capture 时只允许 main 固定路径、固定 hash、无网页全局暴露的最小 page preload。Codex Windows pipe 已观察到的无应用层认证问题不得复制。

## 风险 5：Browser 身份与隐私

Cookie、账号、下载和页面内容可能包含高敏感信息。把它们默认写入 thread、日志或截图会破坏用户信任。

应对：Browser 数据默认留在 partition；模型只接收任务必要且用户授权的内容；日志脱敏；下载和截图显式可见、可审计。

## 风险 6：上游快速漂移

codex app-server 协议、实验能力和产品行为都会变化。一次性“抄齐”会迅速过期。

应对：锁定版本、维护能力账本、自动探针、升级 checklist 和按版本验证，不把旧方法数或旧截图当永恒基线。

## 风险 7：性能和资源

Electron、codex app-server、Gateway、code-mode/sandbox helper 和多个 browser renderer 可能造成启动慢、内存高和退出残留。

应对：纵向切片先测首帧、首个 thread、空闲内存、运行内存、每 view 增量和崩溃恢复；在全量迁移前建立预算。

## 风险 8：路线再次发散

工作台、OPC、模型市场和多 agent 都可能重新吸走主线资源。

应对：04 是优先级唯一真源。P0/P1 外的新方向必须先改决策和 spec，不能从遗留目录自然生长。

## 风险 9：Windows 交付滞后

在 macOS 上跑通 Electron 不代表 Windows 安装、Credential Manager、DPI、`WebContentsView`、焦点、遮挡、签名和更新可用。

应对：Windows 实机纵向切片前置；CI、开发 smoke 和发布验收分开记录。

## 阶段判据

第一阶段是否成功，看：

1. 上游 codex 升级是否可控。
2. Electron 是否成为唯一宿主。
3. Browser 是否安全、可见、可接管、可恢复。
4. 核心 Codex 工作流是否有 Windows E2E。
5. 用户是否把 BlackRain 当成完整产品，而不是开源壳演示。
