# 02 市场与竞品

## 竞争位置

BlackRain 不与 `codex-rs` 竞争，也不自研基础 agent 内核。它位于开源内核与完整桌面产品之间：

```text
开源 codex-rs
  + 桌面宿主能力
  + 产品级交互与恢复
  + Windows 安装交付
  = BlackRain
```

官方 Codex App 是产品能力和体验标杆；开源 `codex-rs` 是唯一内核真源。BlackRain 的竞争力来自补齐两者之间的差距，并保持可跟随、可验证和可自主扩展。

## 主要参照组

### 官方 Codex App

优势是完整产品体验、官方模型和平台整合。BlackRain 不假设能够获知其内部实现，只依据公开文档和合法可观察行为建立能力基线。

对齐目标包括：会话、项目、审批、diff、终端、Browser、恢复、设置和桌面集成。对齐不等于复制品牌、代码或专有资源。

### 开源 Codex 客户端与壳

这类项目可以快速提供 GUI，但常见问题是：

- 停留在协议包装，没有产品级恢复和安装
- 长期绑定某个旧上游版本
- 宿主能力薄弱，浏览器和系统集成难以扩展
- UI、后端和内核边界混杂

BlackRain 必须用版本化能力矩阵、Rust daemon 边界和 Electron 宿主解决这些问题。

### IDE 内 Agent

IDE 插件擅长代码上下文和编辑器内操作，但产品边界受 IDE 限制。BlackRain 是独立桌面 App，可以拥有项目级界面、内置 Browser、独立权限和完整进程生命周期。

### 通用桌面 Agent

通用 Agent 往往强调“操作一切”，但可能缺少 Codex 的 thread、代码变更、审批和工程反馈闭环。BlackRain 先把 Codex 产品做深，不以多 agent、多角色或垂类市场扩张功能表。

## 为什么先做 Browser

Browser 是代码之外最重要的电脑工作 surface，也是检验桌面宿主是否完整的高密度能力：

- 需要持久身份和 Cookie
- 需要可见、可接管的实时页面
- 需要导航、弹窗、下载和权限策略
- 需要 CDP、截图和工具合同
- 需要独立 renderer 的崩溃恢复和资源治理

它同时验证 Electron 选型、agent/用户协作和产品安全边界。

## 差异化路径

短期差异不是“支持更多模型”或“拥有更多插件”，而是：

1. 比普通开源壳更完整的 Codex App 行为。
2. 比 IDE 插件更完整的桌面宿主和 Browser。
3. 比通用 Agent 更严格的 Codex thread、审批、diff 和恢复闭环。
4. 比闭源产品更开放的本地宿主扩展与可审计边界。

## 不使用的市场指标

当前阶段不以工作台数量、插件数量、专家数量或 OPC 自动化流程数衡量进度。有效指标是能力差距关闭率、真实 E2E 通过率、崩溃恢复率、上游升级成本、Windows 安装成功率和高频用户留存。
