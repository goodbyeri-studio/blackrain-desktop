# 02 市场与竞品

> 本文基于 2026-06 的调研。竞品数据多为厂商或第三方口径,看趋势勿信绝对值。

## 大格局:三个互不相同的战场

AI agent 领域到 2026 年已分化成四个战场,2049 App 必须想清楚自己站在哪:

| 战场 | 代表 | 本质 | 变现 |
|---|---|---|---|
| **编排类平台** | Coze、Dify、n8n、Flowise | 让人「搭」出会调 API 的 bot/工作流 | open-core 企业版为主,几乎无 C 端创作者市场 |
| **通用自主 agent** | Manus、Genspark、Flowith | 一个对话框,后台跑,给结果 | credit / 订阅,自营为主,无创作者经济 |
| **办公型桌面 agent** | WorkBuddy、Trae Work、Coze Agent World | 面向知识工作者,在桌面/浏览器/办公软件里完成跨应用任务 | 订阅 / 企业版 / 办公套件入口 |
| **编码 agent** | Codex、Claude Code、Trae、通义灵码 | 面向程序员的开发工具 | 订阅 / 企业版 |

**关键空白**:「面向办公场景、能真正操作电脑(文件/网页/办公软件/系统自动化)的桌面 agent」+「创作者经济(人人可造可卖)」——这两者的结合,迄今**全行业没有成功样板**。这就是 2049 App 瞄准的位置。

### 底层市场命题:解锁每个软件的「机器门」

为什么这个市场存在、且远不止「办公」?因为几乎每个成熟生产力软件都有两道门——给人手用的 **GUI 门**、给机器驱动的**机器门**(脚本/宏/API/格式层)。机器门的能力存在了几十年(Excel VBA、AutoLISP 1986、Acrobat JavaScript……),却被「编程 + 工具 + 调试 + 格式知识」锁住,普通人只走 GUI 门。RPA 市场(2025 年约 47–60 亿美元、约 29% 复合增长)的存在,本身就证明「机器门锁着、体力活只能外包给软件」这个痛点有人肯付费——而 RPA 又脆又贵,正是 AI 要吃的那块。

**2049 的差异不只是「让 agent 操作电脑」,而是把这个解锁拆成两层呈现**:用户按**领域**浏览货架(办公/数据/CAD/财务……),系统按**运行时 + license** 打包(无头开源全量铺 + 宿主门控按需)。完整目录见 [.specs/004-plugin-catalog](../.specs/004-plugin-catalog/)。竞品要么只解锁单一软件的机器门(WPS 困在 WPS 里),要么只做 API 编排(Coze/Dify 够不到本地真软件)——**跨软件机器门 + 本地数据主权 + 创作者经济**这个组合,是结构性空白。

## 头号威胁:办公入口之争(WorkBuddy / Trae Work / Coze)

这是必须正视的最大竞争信号。2049 App 不是再做一个编码工具,而是要进入 WorkBuddy、Trae Work、Coze 正在争夺的办公桌面入口:谁能稳定完成文档、表格、网页、企业系统和跨应用流程,谁就有机会成为下一代办公入口。

## 头号平台威胁:字节 Coze

- **Coze(扣子)** 是字节的「AI app 开发平台」,定位「字节版 GPTs」。三条产品线:`coze.cn`(国内,只接国产模型,主推豆包)、`coze.com`(海外,可接 GPT/Claude)、`Coze Studio`(开源可自托管)。
- **致命的是它的方向**:Coze 2.5「Agent World」+ 3.0 已经在做——给 agent 配**云设备(云电脑/云手机)**、支持**后台 7×24 运行**、甚至能把本地的 **Codex / Claude Code 拉进项目协作**。

**这意味着什么**:我们押注的「让 agent 真能操作电脑」这个差异点,**字节已经上路了**。它不会长期是我们的护城河——它会变成基础设施。

**但 Coze 有两个商业模式决定的死穴**(见下「我们的差异化」),这才是我们的机会。

## 其他玩家速览

**编排平台**
- **Dify**:最「成品应用层」的开源 LLMOps,Agent+RAG+工作流一体,但偏开发者/团队。
- **n8n**:通用自动化起家,AI 是附加能力;自托管规模化后基建成本高。
- **Flowise / Langflow / FastGPT**:各有侧重(LangChain 可视化 / 企业数据 / RAG 知识库),都偏技术。
- 共同点:**全是给开发者/团队的工具,靠卖企业版赚钱,没有 C 端创作者市场。**

**通用 autonomous agent**
- **Manus**(中国团队):自带「虚拟电脑」,自主多步执行。**credit 制被用户反复吐槽「贵且难懂」**——这是定价的重要反面教材。
- **Genspark**:多 agent workspace,产出 PPT/文档/网页,甚至能打真实 AI 电话,对小白友好、偏广度。
- 共同点:让普通人用 agent 的方式 = **对话框 + 后台跑 + 给结果**,而不是让人去「搭」;且基本没有创作者经济。

**编码 agent(我们刻意避开的红海)**
- Trae(字节,~600 万注册,免费)、通义灵码(阿里,号称国内第一)、CodeBuddy(腾讯)、Qwen Code(阿里,Fork 了 gemini-cli)。正面拼这块 = 用短处撞大厂免费产品的长处,必死。

## GPT Store:创作者市场的反面教材

GPT Store 2024 年主打「创作者能赚钱」,结果哑火。死因(多源确证)对我们极有价值:

1. **分成永远「coming soon」**——大多数创作者根本没有变现路径。
2. **发现机制崩了**——新作品淹没在海量里,没有算法分发,大多数「隐形」。
3. **创作者无差异化杠杆**——不能选模型、强制同一 UI,产品被同质化。
4. **无 IP 保护**——好点子被站内无署名抄袭。
5. **搞错付费人群**——为「个人做小助手」设计,但真肯付费的是有预算的企业。

这五条直接转化为 2049 市场层的设计准则,详见 [06 市场与创作者经济](06-市场与创作者经济.md)。

## 我们的差异化:三处字节结构上做不到的地方

既然「操作电脑」会被字节追平,护城河只能押在它**商业模式或战略重心决定的盲区**:

**1. 不锁模型。**
Coze(coze.cn)必然主推豆包——它要卖自己的模型和云。2049 没有模型要卖,可以中立地把每个任务路由到全网最合适的国产模型(编排用 MiniMax/Qwen、写作用 DeepSeek/豆包、生视频用即梦……)。**这是字节商业模式上的死穴,学不来。**

**2. 真给创作者分钱。**
字节做生态是为了流量和模型调用,「让创作者赚到钱」不是它的优先级(其付费插件分成比例至今不公开)。2049 把创作者经济当头等大事——day-1 真分成、透明结算、防抄袭——这是差异化,也是飞轮的燃料。

**3. 垂直深度 + 本地优先。**
字节做的是大而全的「数字社会」。2049 反其道:聚焦把**少数几个垂类的工作台做到惊艳**,且数据本地优先。对网文写手(怕创意泄露)、代账会计(怕账目外流)而言,「数据不出本地」是强卖点,而这与字节的云生态战略天然冲突。

## 关于 Hermes Agent:是上游,不是竞品

2026-06 调研结论:NousResearch 的 Hermes Agent(MIT)虽与我们架构同形,但**不是竞品,是免费上游**。三层不沾——卖给谁(它=全球开发者/极客;我们=中国非开发者业务专家)、怎么赚钱(它=给 Nous 模型/Portal 引流+攒训练数据;我们=国产 token 差价)、护城河(它=开源可抄的 skills;我们=环境复刻引擎+中文垂类插件市场+AI 带小白用)。它修好的 codex 集成我们能 MIT 白嫖。真竞品仍是国内 no-code(字节 Coze 系)。判断依据见 [.specs/003-dual-engine-architecture/decisions.md](../.specs/003-dual-engine-architecture/decisions.md)。

## 结论

2049 App 不是「再做一个 Coze」,而是「**让普通人也能用的、agent 真能动手干活的、不锁模型、给创作者分钱的垂直 agent 平台**」。窗口期有限,执行速度和上述三条护城河的坚定程度,决定成败。
