# 05 模型路由

## 原则

模型路由服务于唯一 `codex-rs` 内核，不产生第二 agent runtime。BlackRain 优先保持 codex 原生 Responses 路径；只有目标模型提供商不满足该合同时，才启用独立 Gateway sidecar。

## 两条模型路径

### 原生 Responses

```text
codex app-server
  -> Responses-compatible endpoint
  -> model provider
```

这是最短路径。只要目标 provider 与当前锁定 codex 合同兼容，就不经过协议翻译。

### Gateway 兼容路径

```text
codex app-server
  -> Responses
  -> BlackRain Model Gateway
  -> Chat Completions-compatible endpoint
  -> model provider / MeiMei API
```

Gateway 只负责协议转换、流式事件、工具调用和上游错误归一化。它不负责 thread、Browser、账号业务或 UI 状态，也不能修改 agent 循环。

## 配置

- App 沿用 Codex 标准 Home 与 `config.toml` schema，并与原生 CLI 共享 provider/model 配置。
- 不创建 BlackRain 专属隐藏 `CODEX_HOME`；任何配置变更必须在 UI 中可见、可追踪且不破坏 CLI 兼容性。
- provider secret 由系统凭据存储保存。
- 配置和日志只保留 provider id、模型 id、路由状态和脱敏错误。
- Electron renderer 和网页内容不得接触 provider secret。

## 与 Browser 的关系

Browser 是 Electron 宿主工具，不是模型路由。页面 Cookie、下载和登录凭据不得进入 Gateway。只有用户授权且任务需要的页面信息，才能通过受控工具结果进入 codex thread。

## 发布闸口

- 当前锁定 codex 版本的真实模型对话
- Responses 非流式与流式合同
- 工具调用、多轮消息、取消和超时
- Gateway 崩溃、重启和错误映射
- Windows Electron 制品中的凭据隔离
- 日志脱敏和 Browser 数据边界

当前 `gateway.py` 是可行性原型，不是生产完成度声明。Gateway 也不是 Electron 迁移或 in-app browser 的前置替代品。
