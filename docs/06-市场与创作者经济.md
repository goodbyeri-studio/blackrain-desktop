# 06 专家经济与工作台市场

> 文件名因既有链接暂保留。本文整篇属于 post-MVP 蓝图；MVP 只分发官方或随包签名工作台，不实现公开上传、审核、交易和分成。

## 市场出售什么

BlackRain 市场的核心商品不是聊天机器人，也不是只有 Prompt 的模板，而是：

> **可安装、可维护、可验证的专家工作台。**

插件和 Skill 可以单独分发，但它们主要是工作台的零件：

| 商品 | 用户购买的价值 | 主要问题 |
|---|---|---|
| Skill | 一套方法 | 易复制，单独交付能力有限 |
| 插件 | 一个工具能力 | 需要用户自己组合和理解 |
| 工作台 | 完整岗位环境 | BlackRain 的核心交易单位 |
| 工作室 | 多岗位业务系统 | 高价值 Pro/B2B 产品 |

## 为什么叫专家经济

供给者不应只被理解为“创作者”或“开发者”。真正有价值的供给来自：

- 行业专家和高阶从业者
- 拥有成熟电脑工作流的人
- 专业工具作者
- 自动化和数据工程人员
- 帮专家完成环境封装的实施者
- 企业内部标准流程负责人

他们出售的不是自己的时间，而是电脑里长期积累的数字生产资产：工具组合、目录、模板、流程、检查规则和维护经验。

## 供给生产链

一个工作台通常需要两类能力共同完成：

```text
领域专家
  提供任务、方法、工具选择、质量标准、失败经验
              +
工作台封装者
  负责 Manifest、依赖、插件、权限、安装、验证、升级
              ↓
         可发布工作台
```

同一个人可以兼具两种角色，但平台不能假设所有领域专家都会写 Markdown、脚本或 Manifest。

后期必须提供：

- 从真实任务自动沉淀 Skill
- AI 辅助整理专家电脑环境
- 可视化依赖和权限声明
- 自动生成安装检查和标准任务
- 封装者与专家联合署名、联合分成

## 冷启动

市场不能从“允许任何人上传”开始。正确顺序是：

1. 官方与真实专家共同做第一套工作台。
2. 让专家自己长期使用，而不是只为上架制作演示。
3. 用真实失败把环境、脚本和验证硬化。
4. 证明陌生用户能在新电脑上安装并完成任务。
5. 再复制到第二位专家和第二个垂类。
6. 形成稳定封装协议后开放有限邀请制作者。
7. 最后才开放公开市场。

第一批市场内容必须少而强。海量低质量工作台会让用户把整个平台判断为玩具。

## 发现机制

用户不是按技术栈找工作台，而是按岗位和结果找：

- “把一批票据整理成可核对台账”
- “建立 A 股基本面研究项目”
- “批量检查投标文件格式和缺项”
- “把 GIS 原始数据清洗成制图工程”

工作台详情页应展示：

- 解决什么任务
- 来自哪位专家
- 需要哪些软件、账号和数据源
- 会访问什么文件和网络
- 示例输入和真实输出
- 已验证系统和模型
- 成功率、耗时和失败边界
- 更新记录、兼容性和退款规则

## 质量和信任

市场上架不只做恶意代码扫描，还要检查产品质量：

- Manifest 完整性
- 第三方 License 和来源
- 安装、升级、回滚和卸载
- 权限与数据流
- 密钥是否安全处理
- 标准任务是否通过
- 输出验证覆盖什么、不覆盖什么
- 商业软件和数据源是否允许分发
- 作者是否有权上传模板、代码和资料

金融、医疗、法律等高责任工作台需要单独分类、免责声明、功能限制和更严格审核。

## 分成原则

如果平台承诺专家可以赚钱，必须在开放市场时同步提供真实结算，而不是“以后再说”。

建议原则：

- 价格和平台抽成透明
- 专家与封装者可拆分分成
- 退款、争议和弃用规则明确
- 使用量和收入可审计
- 不用模型 credit 口径掩盖工作台价格
- B2B 定制和维护可以形成订阅收入

具体比例需要在供给访谈和成本模型后决定，本文不提前写死。

## 防抄与可移植性

纯 Prompt 无法有效防抄。工作台真正难复制的资产应来自：

- 经过验证的脚本和执行件
- 专业模板和数据结构
- 真实任务评测集
- 环境兼容和失败处理
- 持续更新服务
- 专家品牌和用户评价

平台应保护作者商业利益，但不能用不透明锁定伤害用户。用户项目和数据始终属于用户；工作台停更时应有导出、降级和迁移路径。

## GPT Store 的教训

BlackRain 必须避免：

1. 海量同质化条目淹没优质内容。
2. 承诺赚钱却长期没有真实结算。
3. 只卖 Prompt，作者没有持续价值。
4. 没有发现、试用和可信评价机制。
5. 忽视企业和专业用户才是真正有预算的人群。

## 工作室商业化

工作室属于工作台之上的高价值层：多个岗位、共享数据、业务流程、审批和运行看板。

它更适合：

- 一人公司
- 小微团队
- 企业部门标准岗位
- 顾问向客户交付一整套数字团队

但工作室不能早于单工作台成功。没有可靠岗位，就不会有可靠公司。

## 成功指标

市场不以条目数量为第一指标，而应关注：

- 新电脑安装成功率
- 标准任务完成率
- 真实任务周复用率
- 用户节省时间和人工步骤
- 退款与卸载原因
- 工作台更新存活率
- 专家真实收入
- 用户是否愿意把第二个项目继续交给同一工作台
