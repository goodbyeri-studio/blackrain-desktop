# 06 市场与创作者经济

> 这是平台能否成立的最难一关。调研结论很硬:**agent 领域至今没有一个成功的创作者市场。** 谁先跑通,谁就有结构性优势。

## 市场是什么

工作台 / 插件的注册表。懂业务 know-how 的人在这里造工作台和插件,上架、被发现、被使用、赚钱;小白在这里像逛 app 商店一样,找到能替自己干完一整件事的 agent 工作台。

结构上类似 Coze Studio,但唯一且致命的区别:**这里的每一个「应用」编排的是「真能在本地动手干活的 agent」,而非 API 调用的聊天机器人。**

## 冷启动:平台最容易死的地方

双边市场的经典死法:没创作者 → 没好工作台 → 没用户 → 创作者不来。字节 Coze 靠自有流量硬启动,我们没有这个弹药。

调研给出的唯一靠谱解:**single-player(单机自用)优先,市场供给是副产品。**

> 网文写手用「番茄小说工作台」不是为了卖它,是为了自己写爽文赚稿费。他用顺了,这个被反复打磨过的工作台**顺手**就能上架,变成别人能用的供给。

### 点火顺序

```
① 我们自己 + 邀请几个真实从业者,做出 3-5 个惊艳的工作台
        ↓
② 让目标人群自用到尖叫(此时产品对单个用户已经值钱,不依赖市场)
        ↓
③ 这批人沉淀的好工作台/插件,变成市场的第一批供给
        ↓
④ 市场出现流动性,飞轮转起来
```

### 关键原则

- **极窄切入**:先在**一个**垂类(如网文)做出流动性,再扩到下一个。不要一上来铺多个垂类。
- **官方先 seed 供给**:平台自己和邀请的头部创作者先把货架填满,让市场「看起来是活的」。
- **成功指标是流动性,不是用户数**:一个需求能否在合理时间内被满足(找到能用的工作台),才是健康度指标。

## 创作者经济:把 GPT Store 的死因逐条反过来

GPT Store 主打「创作者赚钱」却哑火。它的五个死因,直接转化为 2049 市场层的设计准则:

| GPT Store 死因 | 2049 必须这样做 |
|---|---|
| 分成永远「coming soon」,大多数人没有变现路径 | **分成 day-1 真上线**,学 Coze 用统一结算(用户不必到处充值),按调用/按成果付,**比例公开透明** |
| 发现机制崩了,新作者隐形 | **分发即产品**:榜单 + 场景化推荐 + 算法分发,让新作品能被看见 |
| 创作者无差异化杠杆(强制同一 UI) | 工作台可自定义交付物形态、可挂创作者品牌,避免同质化 |
| 无 IP 保护,被无署名抄袭 | 署名 + 防克隆 + 收益归属机制**前置**,别等做大了再补 |
| 搞错付费人群(为爱好者设计) | 瞄准**专业个体 / 中小企业**(网文写手、跨境卖家、代账会计),他们有真实付费意愿 |

## 变现模式

避开 Manus 的教训——**credit 制「贵且难懂」会劝退普通人**,而真操作电脑的 agent 烧 token 多。所以分层设计:

| 对象 | 模式 | 说明 |
|---|---|---|
| **C 端小白** | **封顶订阅** + 重度按量 | 让用户心里有数,别用 credit 吓人;轻度用户一个月固定价管够 |
| **创作者** | 收入分成(平台抽成) | day-1 真分成、透明结算,这是飞轮燃料 |
| **B 端企业** | 企业版授权 | 私有部署、不锁模型、审计日志、SLA;卖给受监管行业,**这是真利润** |

## 创作者经济的飞轮

```
        小白用户多
       ↗          ↘
  创作者有钱赚      创作者愿意造好工作台
       ↖          ↙
        好工作台多 → 吸引更多小白
```

让这个飞轮转起来的前提,是**创作者真能赚到钱**——这恰恰是字节不优先做、而我们当头等大事做的事(见 [07 护城河与风险](07-护城河与风险.md))。

## 阶段性目标

| 阶段 | 目标 | 健康度信号 |
|---|---|---|
| 点火 | 单一垂类(网文)3-5 个惊艳工作台,自用人群尖叫 | 自用留存、口碑自传播 |
| 流动性 | 该垂类内「找得到能用的工作台」 | 需求被满足的比例 |
| 创作者启动 | 第一批创作者真赚到钱并公开 | 创作者数、创作者收入 |
| 横向扩张 | 复制到下一个垂类(跨境/代账) | 新垂类达到流动性的速度 |
| 平台化 | 造工作台本身也变成普通人能干的事 | 非程序员创作者占比 |
