# Requirements

> ⚠️ **范围标注（2026-07-12）**：本目录是长期插件供给账本，不是 MVP 开发清单。MVP 仅发行 Windows，并用 Office 参考工作台验证底座；下文 ~34 单元 / 7 大类不得被解读为当前已实现或全部待办。术语以 [docs/04](../../docs/04-产品形态.md) 为唯一真源，工作台包以 [.specs/008](../008-expert-workbench-package/) 为执行真源。

## 背景

- 这份 spec 为什么保留：产品形态(术语台阶 = 技能 → 插件 → 工作台 → 工作室)已在 [docs/04-产品形态](../../docs/04-产品形态.md) 定型,需要一张长期可维护的供给侧全景账本,但它不改变当前 Windows-only office MVP 的优先级。
- 核心命题(2026-06 深度调研结论)：每个成熟生产力软件都有**两道门**——给人手用的 **GUI 门**、给机器驱动的**机器门**(脚本/宏/API/格式层)。机器门一直开着，却被「编程 + 工具选择 + 调试 + 文件格式知识」锁住，普通人一辈子只走 GUI 门。AI agent 是第一把能同时给「完整能力 + 自然语言易用」的钥匙。**本 spec 的插件 = 每个软件机器门的适配器(供给侧打包单位)。**
- 相关上游/文档/现有实现：[03 系统架构](../../docs/03-系统架构.md)(能力封装层)、[04 产品形态](../../docs/04-产品形态.md)(术语真源)、[.specs/003 decisions](../003-dual-engine-architecture/decisions.md)(双引擎 + 本地交付环境/推理走云)。

## 用户目标

- 作为谁：不懂代码的办公岗位 / 专业垂类从业者(运营、行政、财务、代账、绘图员、GIS 分析、电商美工……)。
- 想完成什么：用自然语言调动某个专业软件 / 文件格式的**机器门**，把过去只能逐个手工点的活批量、精确地干完。
- 成功后看到/得到什么：在对话里 `@` 一个插件即获得某项原生能力；或挂一个预装好该垂类插件的工作台，按引导把整件事做完。

## 非目标

- 本阶段明确不做：
  - **不实现任何插件代码**——本 spec 是目录与粒度规则的活文档，不含实现。
  - **不做 SCADA / PLC 控制端写入**——工业安全红线，只做只读报表(historian-read)。
  - **不把任务做成插件**——「转竖屏」「改 80 张图框」「出门窗表」「周报看板」是 skill 配方，住在工作台层，不占插件编制。
  - **不把门户填报做成插件**——它无新运行时，是 `browser-auto + desktop-auto + ocr-vision` 之上的编排，定位为工作台。
- 不改变的架构边界：codex 内核原装黑盒不动；网关只管 CODE 路径；插件机制沿用 codex/Hermes 的 skill/MCP/ACP。

## 成功标准

- 文档行为：给出一张**稳定、可长期维护**的候选插件目录——按「引擎/格式适配器」切分，不按任务切分，使插件数量锁在 ~30 量级而任务覆盖面靠数百 skill 配方扩展。
- 用户体验：用户按**领域**浏览(7 大类)，系统按**运行时 + license** 打包(~34 单元)，两层解耦。
- 安全/合规：每个打包单元标注 license 与 `[铺]`(无头开源，进本地胖包)/`[控]`(需用户已装正版宿主软件)；传染性许可证(GPL/AGPL/BSL)依赖一律拦截，沿用 [CONTRIBUTING](../../CONTRIBUTING.md) 红线。
- 性能/稳定性：`[铺]` 包必须能 headless 跑起来(无 GUI 依赖)，可塞进 [.specs/003](../003-dual-engine-architecture/decisions.md) 定的本地胖包。

## 约束

- Codex 内核边界：插件不改内核 agent 循环；通过 skill/MCP/ACP 扩展机制接入。
- `CODEX_HOME` / 配置边界：插件资产放进专属 `CODEX_HOME`，不污染用户原有环境。
- License / 第三方依赖：MIT/Apache/BSD 也必须逐包审计并履行 NOTICE/署名义务；GPL/AGPL/BSL/无许可证依赖按全仓红线直接拦截，不进入仓库或发行包。LGPL 组件的链接方式、可替换性、安装包同分发和许可证义务仍需法务/依赖树/制品审计。`[控]` 包只驱动用户自有正版软件，不分发宿主软件本身。
- 平台差异：MVP 只认 Windows 制品与 Windows 实测；原生 wheel 首先要有 Windows x64 可用制品。macOS/Linux 构建属 post-MVP 上游资产，不进当前验收矩阵。desktop-auto 的 UI Automation 主要面向 Windows。
