# 工作台会话编排决策

## 2026-07-24：所有工作台统一复用 codex app-server

- 决策：普通工作台和软件开发工作台共享原装 codex app-server、Gateway、thread、事件、审批和恢复合同。
- 原因：平台资产应集中在工作台环境和验证层；维护第二套 agent 运行时会复制进程、协议、恢复和安全边界。
- 替代方案：为普通工作台维护独立 agent 进程；不采用。
- 影响范围：运行时架构、模型路由、工作台 surface、激活记录消费方式和 Windows 发布矩阵。

## 2026-07-24：双 surface 是产品视图，不是运行时分叉

- 决策：`workbench` surface 面向任务与成果，`code` surface 面向开发控制；二者只在前端信息架构和能力可见性上不同。
- 原因：普通用户不应承担开发界面复杂度，但底层执行、安全和恢复合同必须唯一。
- 影响范围：路由、状态选择器、可见控件、验收用例和产品文案。

## 2026-07-24：激活记录通过 Session Orchestrator 进入内核

- 决策：工作台包不能直接生成 prompt、内核参数或配置；App/Core 从已验证激活记录生成不可变会话描述符。
- 原因：这样才能保持 App 唯一配置写入者，并在启动和恢复时统一执行权限与资源重验。
- 影响范围：spec 008、shared core、IPC、session store、安全测试和 Office 接线。
